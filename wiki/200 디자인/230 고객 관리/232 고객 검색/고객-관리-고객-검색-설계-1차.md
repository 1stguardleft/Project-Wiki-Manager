# 고객 관리 - 고객 검색 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 고객 관리 / 고객 검색  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** Pageable 기반 검색 API 신설, 이름/전화번호 인덱스 추가. > ℹ️ 변경: 문서 버전이 v1.0에서 v2.0으로 업데이트되었습니다.

## 1. 설계 개요

`GET /api/customers/search`를 신설하고 Spring Data의 `Pageable` + derived query로 부분일치 검색을 제공한다. 1차에는 별도 검색 컴포넌트를 두지 않으며, 클라이언트는 전체 목록 API를 호출 후 자체 필터를 적용한다. > ℹ️ 변경: 1차 설계에서는 별도 검색 컴포넌트를 두지 않았으나, 2차 설계에서는 검색 API가 신설되었습니다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | CustomerController | 검색 API 노출 |
| Service | CustomerService | 파라미터 검증 + 검색 호출 |
| Repository | CustomerRepository | `findByNameContainingIgnoreCaseOrPhoneContaining(name, phone, Pageable)` |

## 3. 데이터 모델

추가 컬럼 없음. 인덱스 추가:

- `idx_customer_name` (name)
- `idx_customer_phone` (phone) > ℹ️ 변경: 데이터 모델에 이름과 전화번호 인덱스가 추가되었습니다.

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/customers/search?name=&phone=&page=&size= | 부분일치 검색 + 페이지네이션 | > ℹ️ 변경: API 인터페이스에 새로운 검색 경로가 추가되었습니다.

## 5. 처리 흐름

1. 파라미터 검증 (둘 중 하나는 필수)
2. size 클램프 (1~100)
3. derived query 실행
4. Page<Customer> → CustomerSearchResponse 매핑 > ℹ️ 변경: 처리 흐름이 추가되었습니다.

## 6. 설계 규칙

- LIKE는 양쪽 와일드카드 `%name%`.
- 대소문자 무시.
- 기본 정렬: createdAt DESC. > ℹ️ 변경: 설계 규칙이 업데이트되었습니다.
