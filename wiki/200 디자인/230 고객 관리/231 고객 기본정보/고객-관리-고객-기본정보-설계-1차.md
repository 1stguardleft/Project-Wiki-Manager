# 고객 관리 - 고객 기본정보 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 고객 관리 / 고객 기본정보  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** email UNIQUE, 활성 주문 보유 시 삭제 차단, 이메일 형식 강화.

## 1. 설계 개요

CRUD에 더해 이메일 unique 검증, 삭제 시 진행 중 주문 검사 로직을 추가한다. 단, email은 unique 제약을 두지 않는다.

## 2. 구성 요소

| 계층       | 구성 요소           | 역할                      |
|------------|---------------------|---------------------------|
| Controller | CustomerController   | CRUD                      |
| Service    | CustomerService      | 이메일/주문 보유 검증    |
| Entity     | Customer             | email UNIQUE              |
| Repository | CustomerRepository    | existsByEmail             |

## 3. 데이터 모델

| 컬럼   | 타입          | 제약                     |
|--------|---------------|--------------------------|
| email  | varchar(120)  | NOT NULL                 |
| (기타) | (1차 동일)   |                          |

## 4. API 인터페이스

| 메서드 | 경로                     | 설명                     |
|--------|--------------------------|--------------------------|
| POST   | /api/customers           | 등록 (이메일 검증)      |
| DELETE | /api/customers/{id}      | 존재 검증 후 삭제       |
| (기타) | (1차 동일)              |                          |

## 5. 처리 흐름

- 등록: 형식·existsByEmail → save (UNIQUE 위반 → 409 변환)
- 삭제: 존재 검증 → delete → 204 (주문 참조 검사 없음)

## 6. 설계 규칙

- DB UNIQUE + Service 사전 체크.
- 응답은 [[공통API응답]] 표준.

| 연관 기능         | 의존 내용               |
|-------------------|------------------------|
| [[주문처리]]      | 활성 주문 검사         |
| [[고객변경이력]]  | 수정 시 이력 적재      |
