# 대시보드 - 집계 통계 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 대시보드 / 집계 통계  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** DepartmentRepository 의존 추가, DTO 필드 1개 추가, 엔드포인트 `/summary`로 단일화.

## 1. 설계 개요

집계 통계는 별도 엔티티 없이 5개 Repository의 `count()`를 한 번에 호출해 묶어 반환하는 read-only 기능이다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | DashboardController | `/api/dashboard/summary` 노출 |
| Service | DashboardService | 5개 도메인 count 합산 |
| Repository | Product/Customer/Employee/Order/Department Repository | count() 제공 |

## 3. 데이터 / 항목

본 서브도메인은 자체 엔티티가 없다. 응답 DTO는 5개 정수 필드를 포함한다.

| 항목 | 타입 | 설명 |
|---|---|---|
| productCount | long | 상품 총 |
| customerCount | long | 고객 총 |
| employeeCount | long | 직원 총 |
| orderCount | long | 주문 총 |
| departmentCount | long | 부서 총 (2차 신규) | > ℹ️ 변경: DTO 필드가 1개 추가되었습니다.

## 4. 인터페이스 (API)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/dashboard/summary | 5개 카운트 일괄 조회 (1차 `/stats` 폐기) | > ℹ️ 변경: 엔드포인트가 `/summary`로 변경되었습니다.

## 5. 처리 흐름

1. 클라이언트 호출
2. Service가 5개 Repository의 `count()`를 호출 (병렬 가능)
3. DTO에 담아 단일 응답 반환

## 6. 설계 규칙

- 캐시 미적용(실시간).
- 응답은 공통 API 응답 표준을 따른다.
- 1차의 `/stats` 경로는 한 릴리스간 유지 후 폐기(deprecated). > ℹ️ 변경: `/stats` 경로가 폐기되었습니다.
