# 대시보드 - 운영 알림 지표 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 대시보드 / 운영 알림 지표  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** threshold 파라미터화, staleOrders(장기 미처리) 지표 추가.

## 1. 설계 개요

기존 `pendingOrders`·`lowStockItems`에 `staleOrders`(24시간 이상 PENDING)를 추가하고, 재고 부족 임계값을 외부에서 조정 가능하게 변경한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | DashboardController | `/api/dashboard/alerts` 노출 |
| Service | DashboardService | 세 지표를 묶어 계산 |
| Repository | OrderRepository | `countByStatus`, `countByStatusAndOrderDateBefore` |
| Repository | ProductRepository | `countByQuantityLessThan(int)` |

## 3. 데이터 / 항목

| 항목 | 타입 | 설명 |
|---|---|---|
| pendingOrders | long | PENDING 카운트 |
| lowStockItems | long | quantity < threshold |
| staleOrders | long | PENDING & orderDate < now-24h |
| threshold | int | 적용 임계값 echo |

## 4. 인터페이스 (API)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/dashboard/alerts?threshold=N | 세 지표 일괄 조회 |

## 5. 처리 흐름

1. threshold 파라미터 검증 (1~1000 클램프)
2. 세 카운트 쿼리 호출
3. DTO 묶어 반환

## 6. 설계 규칙

- threshold 기본 10, 음수/문자 시 기본값.
- 24시간 기준은 코드 상수로 노출(추후 외부화 검토).
