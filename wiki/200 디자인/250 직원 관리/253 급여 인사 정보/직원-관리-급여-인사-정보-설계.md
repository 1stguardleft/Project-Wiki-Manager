# 직원 관리 - 급여/인사 정보 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 직원 관리 / 급여/인사 정보  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** position enum, salary 범위 검증, hireDate 미래 한도.

## 1. 설계 개요

Employee.position을 enum 컬럼으로 변경하고, salary/hireDate에 검증을 추가한다. 또한, salary의 음수 검증은 Service에서 처리한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Enum | EmployeePosition | STAFF/MANAGER/DIRECTOR/EXECUTIVE |
| Entity | Employee | position enum 컬럼, 자유 문자열 처리 |
| Service | EmployeeService | salary/hireDate 검증, salary 음수 검증 |

## 3. 데이터 모델 (변경)

| 컬럼 | 타입 | 제약 |
|---|---|---|
| position | varchar(20) | NOT NULL, enum | > ℹ️ 변경: position의 타입이 varchar(40)에서 varchar(20)으로 변경되었고, enum으로 설정됨. 자유 문자열은 기존 데이터를 STAFF로 매핑 후 운영자가 정정. |
| salary | bigint | CHECK 1,000,000 ≤ salary ≤ 200,000,000 | > ℹ️ 변경: salary의 제약 조건이 nullable, ≥ 0에서 CHECK 1,000,000 ≤ salary ≤ 200,000,000으로 변경됨. |
| hire_date | date | 1년 미래 한도 | > ℹ️ 변경: hire_date의 제약 조건이 nullable에서 1년 미래 한도로 변경됨. |

## 4. API 인터페이스

별도 엔드포인트 없음 (Employee CRUD 응답에 포함).

## 5. 처리 흐름

- 등록/수정: enum 변환 → 실패 시 400, salary 범위 검증, hire_date 한도 검증, salary 음수 검증.

## 6. 설계 규칙

- enum 외 값 거부.
- 마이그레이션: 기존 position 자유 텍스트는 STAFF로 일괄 매핑 후 운영자가 정정.
