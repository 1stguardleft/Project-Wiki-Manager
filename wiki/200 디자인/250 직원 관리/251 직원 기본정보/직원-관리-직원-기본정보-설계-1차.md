# 직원 관리 - 직원 기본정보 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 직원 관리 / 직원 기본정보  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** email UNIQUE, hire_date 자동 채움.

## 1. 설계 개요

CRUD 흐름에 이메일 사전 검증을 추가하고, hire_date null 입력 시 LocalDate.now()로 보정한다.

## 2. 구성 요소

| 계층       | 구성 요소           | 역할                       |
|------------|---------------------|----------------------------|
| Controller | EmployeeController   | CRUD                       |
| Service    | EmployeeService      | UNIQUE 사전 체크 + hire_date 보정 |
| Entity     | Employee             | email UNIQUE               |
| Repository | EmployeeRepository    | existsByEmail              |

## 3. 데이터 모델

| 컬럼           | 타입          | 제약                       |
|----------------|---------------|----------------------------|
| id             | bigint        | PK                         |
| name           | varchar(80)   | NOT NULL                   |
| email          | varchar(120)  | NOT NULL, UNIQUE           |
| phone          | varchar(30)   | NOT NULL                   |
| position       | varchar(40)   | NOT NULL                   |
| salary         | bigint        | nullable                   |
| hire_date      | date          | NOT NULL (자동 채움)       |
| department_id  | FK            | NOT NULL                   |
| created_at     | timestamp     | 자동                       |

## 4. API 인터페이스

| 메서드 | 경로                  | 설명   |
|--------|----------------------|--------|
| POST   | /api/employees       | 등록   |
| GET    | /api/employees       | 목록   |
| GET    | /api/employees/{id}  | 상세   |
| PUT    | /api/employees/{id}  | 수정   |
| DELETE | /api/employees/{id}  | 삭제   |
| GET    | /api/employees/unassigned | 미배치 목록 |

## 5. 처리 흐름

- 등록: 형식 검증 → existsByEmail → save (DB UNIQUE 위반 시 409 변환) → 201  
- hire_date null → today() 보정 후 저장

## 6. 설계 규칙

- DB UNIQUE + Service 사전 체크.  
- department_id NOT NULL.  
- 응답은 [[공통API응답]] 표준.
