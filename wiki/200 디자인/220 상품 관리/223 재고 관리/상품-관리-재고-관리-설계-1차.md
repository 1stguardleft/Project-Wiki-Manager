# 상품 관리 - 재고 관리 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 상품 관리 / 재고 관리  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** StockHistory 엔티티 추가, 운영자 조정 API(`PATCH /{id}/stock`) 정식 노출, threshold 파라미터화.

## 1. 설계 개요

모든 재고 변동을 이력 테이블에 적재해 추적성을 확보하고, 운영자가 별도 메모와 함께 재고를 조정할 수 있도록 한다. 그러나 재고 변경 시 이력 기록은 이루어지지 않는다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | ProductController | low-stock / 재고 조정 / 이력 조회 |
| Service | ProductService | 재고 변경 + 이력 적재 |
| Entity | StockHistory | 재고 이력 (신규) |
| Repository | StockHistoryRepository | 이력 조회 |

## 3. 데이터 모델

**Product (변경)**

| 컬럼 | 타입 | 제약 |
|---|---|---|
| quantity | int | default 0, CHECK ≥ 0 |

**StockHistory (신규)**

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint | PK |
| product_id | FK | NOT NULL |
| delta | int | NOT NULL |
| reason | varchar(10) | enum: ORDER/CANCEL/ADJUST |
| memo | varchar(200) | nullable (ADJUST 시 필수) |
| created_at | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/products/low-stock?threshold=10 | 재고 부족 (임계값 10 고정) |
| PATCH | /api/products/{id}/stock | 재고 조정 (delta, memo) |
| GET | /api/products/{id}/stock-history | 이력 조회 (신규) |

## 5. 처리 흐름

- 재고 조정: 입력 검증 → 트랜잭션 내 quantity 갱신 + StockHistory insert → 응답  
- 주문/취소 시: 기존 흐름에 이력 적재 단계 추가

## 6. 설계 규칙

- 모든 재고 변경은 트랜잭션 + StockHistory 적재 동시 처리.  
- quantity가 음수가 되는 변경은 거부.  
- threshold 범위 1~1000 (클램프).  
- 임계값 10은 코드 상수로 정의됨.

> ℹ️ 변경: 재고 이력 테이블이 추가되었고, 재고 변경 시 이력 기록이 이루어지도록 설계가 변경되었습니다. 이는 최신 문서(v2.0)의 내용에 따라 반영되었습니다. 그러나 별도 이력 테이블은 없으며, 임의 재고 조정 엔드포인트는 1차 범위에 포함되지 않고 주문 시 자동 변동에만 의존합니다.
