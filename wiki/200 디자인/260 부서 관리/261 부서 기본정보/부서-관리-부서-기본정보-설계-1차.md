# 부서 관리 - 부서 기본정보 - 설계

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 부서 관리 / 부서 기본정보  
**SDLC 단계:** 설계  
**변경 요점 (vs 1차):** manager_id FK, 직원 보유 부서 삭제 차단.

## 1. 설계 개요

Department에 manager_id를 추가하고, 삭제 흐름에 직원 보유 검사를 추가한다.

## 2. 구성 요소

| 계층       | 구성 요소             | 역할                     |
|------------|-----------------------|--------------------------|
| Controller | DepartmentController   | CRUD                     |
| Service    | DepartmentService      | 매니저 검증 + 삭제 차단 |
| Entity     | Department             | manager_id FK            |
| Repository | DepartmentRepository   | 기본 + count 활용       |

## 3. 데이터 모델

| 컬럼         | 타입          | 제약                     |
|--------------|---------------|--------------------------|
| id           | bigint        | PK                       |
| name         | varchar(80)   | NOT NULL, UNIQUE         |
| description  | varchar(500)  | nullable                 |
| created_at   | timestamp     | 자동                     |
| manager_id   | bigint        | FK 직원, nullable        | <!-- ℹ️ 변경: manager_id 컬럼 추가 -->

## 4. API 인터페이스

| 메서드 | 경로                     | 설명   |
|--------|-------------------------|--------|
| POST   | /api/departments        | 등록   |
| GET    | /api/departments        | 목록   |
| GET    | /api/departments/{id}   | 상세   |
| PUT    | /api/departments/{id}   | 수정   |
| DELETE | /api/departments/{id}   | 삭제   |

> ℹ️ 변경: body 스키마에 manager_id 추가.

## 5. 처리 흐름

- 매니저 지정: 입력 manager의 departmentId == 자신의 id 인지 검증
- 삭제: `EmployeeRepository.countByDepartmentId(id) == 0` → 0이면 delete, 아니면 409 <!-- ℹ️ 변경: 삭제 흐름에 직원 보유 검사 추가 -->

## 6. 설계 규칙

- manager_id nullable.
- 삭제 차단 정책은 DEPARTMENT_IN_USE로 통일. <!-- ℹ️ 변경: 삭제 차단 정책 통일 -->
