# DevOps 실무: CI/CD와 Observability 중심

## 요약
DevOps 실무에서는 CI/CD 자동화와 Observability 체계를 함께 강화해야 한다. 빠른 배포와 안정적인 운영을 동시에 달성하기 위해 자동화, 가시성, 표준화가 함께 설계되어야 한다.

## 주요 내용

### CI/CD 파이프라인
- **일반적인 단계**: 코드 커밋 → 빌드 → 테스트 → 보안 스캔 → 아티팩트 생성 → 스테이징 배포 → 운영 배포
- **효과**: 배포 빈도 향상, 변경 리드 타임 단축
- 배포 자동화만 있고 운영 가시성이 부족하면 장애 감지와 원인 파악이 어려움

### Observability
- **정의**: 메트릭, 로그, 트레이스를 통해 시스템 상태를 이해하는 능력
- 배포 이후 서비스 품질을 지속적으로 확인하기 위해 모니터링과 알림 체계 필수
- **MTTR(평균 복구 시간)** 단축을 위해 문제 탐지와 원인 분석 속도가 중요

### Kubernetes 기반 환경
- **주요 도구**: GitOps, Helm, Argo CD
- 선언적 배포와 변경 이력 추적을 강화해 운영 일관성 향상

### Platform Engineering 관점
- 플랫폼 팀: 공통 CI/CD 템플릿과 표준 관측 스택 제공
- 애플리케이션 팀: 서비스 개발에 집중
- DevOps 운영 품질을 조직 전체로 확장하는 데 유리

## 핵심 주장
- DevOps의 핵심은 배포 속도만 높이는 것이 아니라, 빠른 배포와 안정적인 운영을 동시에 달성하는 것이다.
- 이를 위해 **자동화**, **가시성**, **표준화**가 함께 설계되어야 한다.
