# 프로젝트 테일러링 가이드

## 요약
이 문서는 표준 개발 프로세스를 프로젝트 규모, 팀 구성, 일정 제약, 외부 의존성에 따라 조정하는 기준을 정의한다. 어떤 활동을 유지하고 어떤 활동을 축소하거나 생략할지 합의하는 데 목적이 있다.

## 적용 범위
- 신규 웹 서비스 개발 프로젝트
- 3개월 이내 단기 구축 과제
- 내부 개발자 4명 이하 소규모 팀
- 외부 솔루션 연동 포함 프로젝트

## 테일러링 원칙

### 필수 유지 활동
프로젝트 규모와 관계없이 유지:
- 요구사항 정의 및 승인
- 아키텍처 검토
- 개발 산출물 형상관리
- 테스트 결과 기록
- 배포 전 체크리스트 확인

### 경량화 대상
상황에 따라 축소 가능:
- 상세 설계 문서 분량
- 주간 보고 형식
- 테스트 케이스 문서 수준
- 회의 빈도와 참석 범위

### 생략 금지 항목
일정이 촉박해도 생략 불가:
- 개인정보/인증 관련 보안 검토
- 운영 이관 문서
- 장애 대응 연락 체계
- 요구사항 변경 이력 관리

## 프로젝트 특성별 조정

### 일정이 매우 짧은 경우
- 상세 설계는 핵심 화면, API, 데이터 모델 중심으로만 작성
- 비핵심 화면은 간단한 메모로 대체 가능
- 일일 스탠드업 15분 이내 제한
- 주간 보고는 작업 보드 스냅샷으로 대체 가능

### 외부 연동 비중이 높은 경우
- 인터페이스 명세 별도 관리
- 연동 실패 시 재처리 정책 필수 정의
- Mock 환경과 실제 환경 검증 구분
- 외부 시스템 담당자 연락처/대응 SLA 운영 문서 포함

### 팀 규모가 작은 경우
- PM, 개발, 테스트 역할 겸임 가능
- 코드 리뷰 1인 승인 허용
- 품질 점검은 체크리스트 기반 수행
- 회의록은 의사결정 있는 경우만 작성

## 산출물 테일러링 정책
| 산출물 | 축소 가능 조건 | 생략 가능 |
|--------|----------------|----------|
| 프로젝트 계획서 | 소규모 시 간략 버전 | 불가 |
| 요구사항 정의서 | 사용자 스토리 기반 간략화 | 불가 |
| 상세 설계서 | 핵심 기능 중심 축소 | 조건부 |
| 테스트 케이스 | 핵심 시나리오 우선 | 조건부 |
| 운영 이관 문서 | 분량 축소 | 불가 |
| 주간 보고서 | 보드 캡처/요약 메모 대체 | 가능 |

## 역할별 책임
- **PM**: 테일러링 범위 승인, 요구사항 변경 관리, 대외 커뮤니케이션 총괄
- **아키텍트/리드 개발자**: 설계 산출물 최소 기준 정의, 기술 표준 결정, 품질 리스크 검토
- **개발자**: 구현 산출물 작성, 코드 리뷰 수행, 테스트 결과 기록
- **QA/테스트 담당**: 핵심 시나리오 검증, 결함 추적, 배포 전 점검 결과 정리

## 운영 전환 기준
운영 전환 전 필수 확인 항목:
- 배포 절차 문서 최신화
- 장애 대응 연락망 공유
- 운영 계정 및 권한 확인
- 로그 확인 방법 문서화
- 백업 및 복구 절차 확인

## 핵심 주장
1. 요구사항 정의, 아키텍처 검토, 형상관리, 테스트 기록, 배포 전 체크리스트는 프로젝트 규모와 관계없이 필수 유지
2. 보안 검토, 운영 이관 문서, 장애 대응 연락 체계, 요구사항 변경 이력 관리는 일정 촉박해도 생략 금지
3. 상세 설계 문서, 주간 보고, 테스트 케이스 문서, 회의 빈도는 상황에 따라 축소 가능
4. 일정 20% 이상 변동, 외부 연동 추가, 인력 변경, 보안 요구사항 추가, 운영 범위 확대 시 테일러링 기준 재검토
