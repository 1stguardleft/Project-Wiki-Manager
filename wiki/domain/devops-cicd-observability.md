# DevOps 실무: CI/CD와 Observability

## DevOps와 Platform Engineering 개요

DevOps는 개발팀과 운영팀의 협업을 강화해 소프트웨어를 더 빠르고 안정적으로 배포하기 위한 문화와 실천 방식이다. 핵심 목표는 배포 주기를 줄이고 장애 복구 시간을 단축하며, 변경 실패율을 낮추는 것이다.

최근에는 DevOps를 단순히 개발과 운영의 협업으로만 보지 않고, 내부 개발자 플랫폼 관점에서 확장하는 경우가 많다. Platform Engineering은 개발팀이 공통적으로 사용하는 배포 템플릿, 인프라 추상화, 서비스 카탈로그, 표준 운영 가이드를 제품처럼 제공하는 접근이다.

실무에서는 DevOps 도입이 곧 툴 도입만을 의미하지 않는다. 협업 구조, 책임 공유, 빠른 피드백 루프, 운영 가시성 확보가 함께 성립해야 효과가 난다.

## CI/CD와 Observability의 관계

DevOps를 실제로 운영하는 팀은 CI/CD 자동화와 Observability 체계를 함께 강화하는 경우가 많다. 배포 자동화만 있고 운영 가시성이 부족하면 장애를 빨리 감지하거나 원인을 파악하기 어렵기 때문이다.

## CI/CD 파이프라인

CI/CD 파이프라인의 일반적인 단계는 코드 커밋, 빌드, 테스트, 보안 스캔, 아티팩트 생성, 스테이징 배포, 운영 배포다. 이 흐름이 자동화되면 배포 빈도를 높일 수 있고, 변경 리드 타임도 줄어든다.

대표적인 DevOps 실천 항목으로는 CI/CD 파이프라인, IaC, 모니터링, 자동화 테스트, 점진적 배포가 있다. CI는 코드 변경을 자주 통합하고 자동 검증하는 흐름이고, CD는 검증된 변경을 운영 환경까지 일관되게 배포하는 체계를 뜻한다.

## CI/CD 파이프라인 도구

CI/CD 파이프라인은 빌드, 테스트, 배포를 자동화하는 흐름으로 구성된다. 이 과정에서 사용하는 도구는 조직의 운영 방식과 배포 전략에 따라 달라질 수 있다.

### Jenkins

Jenkins는 전통적인 자동화 서버로 많이 사용된다. 빌드, 테스트, 패키징 작업을 파이프라인으로 구성할 수 있고 플러그인을 통해 기능을 확장할 수 있다. 온프레미스 환경이나 복잡한 커스텀 파이프라인이 필요한 경우에 자주 사용된다.

### Argo CD

Argo CD는 GitOps 기반 배포 도구로 사용된다. 애플리케이션 배포 상태를 Git 저장소 기준으로 동기화하고 Kubernetes 환경에 반영하는 방식에 적합하다. 선언형 배포 운영과 배포 이력 추적이 필요한 경우에 활용된다.

### 도구 선택 시 고려사항

- 빌드와 테스트 자동화 중심인지
- 배포 자동화와 운영 동기화 중심인지
- Kubernetes 기반 환경인지
- GitOps 운영 모델을 채택하는지

## Observability

Observability는 메트릭, 로그, 트레이스를 통해 시스템 상태를 이해하는 능력을 뜻한다. DevOps 팀은 배포 이후 서비스 품질을 지속적으로 확인해야 하므로 모니터링과 알림 체계가 필수적이다. 특히 평균 복구 시간(MTTR)을 줄이기 위해서는 문제 탐지와 원인 분석 속도가 중요하다.

## Kubernetes 기반 환경

Kubernetes 기반 환경에서는 GitOps, Helm, Argo CD 같은 도구가 자주 함께 언급된다. 이들은 선언적 배포와 변경 이력 추적을 강화해 운영 일관성을 높이는 데 도움을 준다.

Kubernetes는 많은 조직에서 DevOps와 Platform Engineering의 공통 기반으로 사용된다. 컨테이너 오케스트레이션, 선언적 배포, 자동 복구, 스케일링 기능 덕분에 표준화된 운영 체계를 만들기 쉽다.

## Platform Engineering 관점

Platform Engineering 관점에서는 공통 CI/CD 템플릿과 표준 관측 스택을 플랫폼 팀이 제공하고, 애플리케이션 팀은 그 위에서 서비스 개발에 집중하도록 역할을 나누기도 한다. 이런 구조는 DevOps 운영 품질을 조직 전체로 확장하는 데 유리하다.

## DevOps 성숙도 평가

DevOps 성숙도를 평가할 때 자주 참고하는 지표는 배포 빈도, 변경 리드 타임, 변경 실패율, 평균 복구 시간(MTTR)이다. 이 지표들은 팀이 빠르게 배포하면서도 안정성을 유지하는지 판단하는 데 사용된다.

## DevOps의 핵심

DevOps의 핵심은 배포 속도만 높이는 것이 아니라, 빠른 배포와 안정적인 운영을 동시에 달성하는 것이다. 이를 위해 자동화, 가시성, 표준화가 함께 설계되어야 한다.
