# 전역 예외 처리 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 공통/인프라 / 전역 예외 처리  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** ErrorCode enum, BusinessException, 핸들러 4종 분리. > ℹ️ 변경: 문서 버전이 v1.0에서 v2.0으로 업데이트되었습니다.

## 1. 구현 범위

ErrorCode enum, BusinessException 도입, GlobalExceptionHandler에 핸들러 4종 추가. > ℹ️ 변경: 구현 범위가 확장되었습니다.

## 2. 구현 항목 체크리스트

- [ ] `enum ErrorCode { VALIDATION_FAILED, NOT_FOUND, DUPLICATE_SKU, ... }` 카탈로그
- [ ] `class BusinessException(ErrorCode code, String message) extends RuntimeException`
- [ ] `@ExceptionHandler` 4종 추가 (Validation/NotFound/Conflict/Unknown)
- [ ] DataIntegrityViolationException → 제약명 분석 → DUPLICATE_*
- [ ] 도메인 Service의 throw를 BusinessException으로 통일
- [ ] 로그 형식 표준화 (errorCode 포함)
- [ ] 로그에 stacktrace 포함
- [ ] 모든 도메인에서 발생한 예외가 일관 응답
- [ ] 500 일괄로 정보 손실 | 1차 범위, 2차에서 세분화
- [ ] 통합 테스트

## 3. 적용 기술

- Java enum
- Spring `@ControllerAdvice`
- SLF4J + MDC(errorCode) > ℹ️ 변경: 적용 기술에 Java enum과 MDC(errorCode)가 추가되었습니다.

## 4. 단계별 작업 순서

1. ErrorCode/BusinessException
2. 핸들러 4종
3. 도메인 throw 통일
4. 로그 표준
5. 통합 테스트 > ℹ️ 변경: 단계별 작업 순서가 추가되었습니다.

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 1차 일괄 500 처리 코드 누락 | Exception 핸들러는 마지막 catch-all로 유지 |
| 제약명 분석이 DB 종류에 따라 다름 | 제약명 표준 정의 + 테스트로 보장 | > ℹ️ 변경: 위험 요소가 업데이트되었습니다.

## 6. 검증 포인트

- 각 예외 타입별 코드/메시지 정확
- 모든 도메인이 BusinessException 또는 표준 예외 사용 > ℹ️ 변경: 검증 포인트가 업데이트되었습니다.

## 7. 연관 작업

| 연관 | 관계 |
|---|---|
| [[공통API응답]] | 응답 작성 | > ℹ️ 변경: 연관 작업이 업데이트되었습니다.
