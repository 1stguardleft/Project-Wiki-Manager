# 상품 관리 - 재고 관리 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 상품 관리 / 재고 관리  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** StockHistory 엔티티/Repository 신설, 트랜잭션 내 이력 적재, threshold 파라미터 처리, 음수 차단.

## 1. 구현 범위

StockHistory 엔티티 + Repository를 신설하고, ProductService의 재고 변경 메서드에 이력 적재 로직을 추가한다. `PATCH /api/products/{id}/stock` 엔드포인트도 정식 추가.

## 2. 구현 항목 체크리스트

- [ ] StockHistory 엔티티 정의 (5개 컬럼)
- [ ] StockHistoryRepository 인터페이스
- [ ] `ProductService.adjustStock(id, delta, reason, memo)` 메서드
- [ ] 트랜잭션 내 `quantity += delta` + StockHistory insert (동시 처리)
- [ ] 음수 결과 → INSUFFICIENT_STOCK 예외
- [ ] `PATCH /api/products/{id}/stock` 핸들러
- [ ] `GET /api/products/{id}/stock-history` 핸들러
- [ ] threshold 클램프 (1~1000)
- [ ] 통합 테스트 (동시 호출 시나리오 포함)

## 3. 적용 기술

- `@Transactional` (Spring)
- 비관적/낙관적 락 검토 (race condition 방지)
- DTO 검증

## 4. 단계별 작업 순서

1. StockHistory 엔티티/Repo
2. adjustStock 메서드
3. 주문/취소 흐름에 이력 적재 통합
4. 컨트롤러
5. 통합 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 동시 주문/조정 race condition | `@Transactional` + 비관적 락 또는 재시도 적용 |
| 이력 테이블 폭증 | 인덱스(`product_id, created_at`), 보존 정책 후속 검토 |

## 6. 검증 포인트

- 주문 → quantity 감소 + StockHistory(ORDER) 적재
- 취소/삭제 → quantity 복원 + StockHistory(CANCEL) 적재
- ADJUST 시 memo 누락 → 400
