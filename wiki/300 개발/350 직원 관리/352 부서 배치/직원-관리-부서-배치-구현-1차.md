# 직원 관리 - 부서 배치 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 직원 관리 / 부서 배치  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** nullable 변경, unassigned 조회, 부서 변경 이력 적재.

## 1. 구현 범위

DDL NULL 허용, EmployeeDepartmentHistory 엔티티/Repo 신설, Service.update에 부서 변경 감지 + 적재.

## 2. 구현 항목 체크리스트

- [ ] DDL: department_id NOT NULL → NULL 허용 > ℹ️ 변경: department_id의 NULL 허용으로 변경되었습니다.
- [ ] EmployeeDepartmentHistory 엔티티/Repository
- [ ] EmployeeService.update: from/to 비교 → 변경 시 이력 insert
- [ ] `GET /api/employees/unassigned` 핸들러 (`findByDepartmentIdIsNull`)
- [ ] `GET /api/employees/{id}/department-history` 핸들러
- [ ] 단위/통합 테스트
- [ ] 부서 배치 전 직원 등록 필요 케이스 | 1차에는 임시 부서 사용, 2차에서 nullable 도입 검토
- [ ] 부서별 조회 정확
- [ ] 미존재 부서 등록 → 404

## 3. 적용 기술

- @Transactional
- derived query `findByDepartmentIdIsNull`

## 4. 단계별 작업 순서

1. DDL 변경  
2. 이력 엔티티  
3. Service 변경 감지  
4. 핸들러  
5. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 1차 NOT NULL 제약과 모순된 운영 데이터 | 마이그레이션 시 검증 |

## 6. 검증 포인트

- null → A → B 시 이력 row 2건
- unassigned 조회 정확
- 부서별 조회 정확
