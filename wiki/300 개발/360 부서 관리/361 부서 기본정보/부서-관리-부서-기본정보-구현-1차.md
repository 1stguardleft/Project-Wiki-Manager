# 부서 관리 - 부서 기본정보 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 부서 관리 / 부서 기본정보  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** manager_id 컬럼/검증, 삭제 차단 정책.

## 1. 구현 범위

DDL manager_id 추가, Service에 매니저/소속 검증 로직 추가.

## 2. 구현 항목 체크리스트

- [ ] DDL: `ALTER TABLE department ADD COLUMN manager_id BIGINT NULL REFERENCES employee(id)`
- [ ] Department 엔티티에 manager_id 추가
- [ ] DepartmentService에 매니저 일치 검증
- [ ] EmployeeRepository.countByDepartmentId 활용 → 삭제 차단
- [ ] DepartmentRepository.existsByName 활용 → 중복 등록 검증
- [ ] DepartmentService CRUD 구현
- [ ] DepartmentController 핸들러 구현
- [ ] [[전역예외처리]]: DEPARTMENT_IN_USE / INVALID_MANAGER
- [ ] @NotBlank name 검증
- [ ] 통합 테스트

## 3. 적용 기술

- Spring Boot, JPA, Bean Validation, JPA FK
- Service 사전 검증

## 4. 단계별 작업 순서

1. DDL → 2. 엔티티 → 3. 검증 로직 → 4. 삭제 차단 → 5. 예외 매핑 → 6. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 직원이 소속된 부서 삭제 | 1차 허용, 2차 차단 검토 |  
| 1차 정책으로 직원 보유 부서가 이미 삭제됨 | 마이그레이션 시 정리 보고서 | > ℹ️ 변경: 위험 요소에 대한 대응 추가.

## 6. 검증 포인트

- 중복 등록 → 409
- 다른 부서 직원을 manager로 지정 → 400
- 직원 보유 삭제 → 409
- 정상 CRUD 동작
