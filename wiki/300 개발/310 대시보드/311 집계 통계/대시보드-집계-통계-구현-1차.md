# 대시보드 - 집계 통계 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 대시보드 / 집계 통계  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** DepartmentRepository 주입, DTO 필드 1개 추가, 엔드포인트 신설 + 1차 경로 한시 유지.

## 1. 구현 범위

DashboardService에 DepartmentRepository 주입 추가, SummaryResponse DTO를 신설하고 `/api/dashboard/summary`를 노출. 1차 `/stats`는 deprecated 응답 헤더와 함께 한 릴리스 유지. 

> ℹ️ 변경: 구현 범위에 대한 설명이 업데이트되었습니다.

## 2. 구현 항목 체크리스트

- [ ] SummaryResponse DTO 정의 (5개 필드)
- [ ] DashboardService에 DepartmentRepository 주입
- [ ] Service 메서드 `getSummary()` 작성
- [ ] Controller에 `GET /api/dashboard/summary` 추가
- [ ] 1차 `/stats`에 `Deprecation` 헤더 추가
- [ ] 단위 테스트 + 통합 테스트

> ℹ️ 변경: 체크리스트 항목이 업데이트되었습니다.

## 3. 적용 기술

- Spring Boot 3.x
- Spring Data JPA `count()`
- HTTP `Deprecation` 헤더 표준 활용

> ℹ️ 변경: 적용 기술이 업데이트되었습니다.

## 4. 단계별 작업 순서

1. DTO/Service → 2. Controller 신설 → 3. `/stats` deprecate 처리 → 4. 테스트

> ℹ️ 변경: 단계별 작업 순서가 업데이트되었습니다.

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 클라이언트가 `/stats`만 사용 중 | 양 엔드포인트 동시 유지 + 공지 |
| 카운트가 5개로 늘어 메서드 비대화 | 메서드를 한 곳에 모으되 가독성 위해 변수명 명확화 |

> ℹ️ 변경: 위험 요소가 업데이트되었습니다.

## 6. 검증 포인트

- 부서 0건/100건 환경에서 departmentCount 정확성
- `/stats`와 `/summary`가 동일 카운트 결과를 반환하는지(부서 제외/포함만 차이)

> ℹ️ 변경: 검증 포인트가 업데이트되었습니다.
