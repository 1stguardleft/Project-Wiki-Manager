# 주문 관리 - 주문 상태 관리 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 주문 상태 관리  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** 전이 매트릭스 + 검증 메서드 추가.

## 1. 구현 범위

OrderStatus enum에 허용 전이를 코드화하고, OrderService.updateStatus에서 검증 후 변경.

## 2. 구현 항목 체크리스트

- [ ] `enum OrderStatus { PENDING, CONFIRMED, SHIPPED, DELIVERED, CANCELLED }`
- [ ] `static EnumMap<OrderStatus, EnumSet<OrderStatus>> TRANSITIONS`
- [ ] `OrderStatus.canTransitTo(target)` 메서드
- [ ] OrderService.updateStatus(id, target): canTransitTo 검사
- [ ] 위반 시 INVALID_TRANSITION 예외
- [ ] CANCELLED 분기 → ProductService.restoreStock 호출
- [ ] 단위/통합 테스트 (전체 5×5 매트릭스)

## 3. 적용 기술

- Java enum + JPA `@Enumerated(STRING)` + EnumMap/EnumSet
- DTO @NotNull
- @Transactional

## 4. 단계별 작업 순서

1. 매트릭스 정의  
2. enum 메서드  
3. Service 적용  
4. 5×5 테스트 매트릭스  

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 잘못된 전이로 운영 데이터 오염 | 1차 허용, 2차에 전이 규칙 명문화 |
| 1차 자유 전이를 사용 중인 클라이언트 | 마이그레이션 가이드 + INVALID_TRANSITION errorCode 명시 |

## 6. 검증 포인트

- enum 외 값 거부
- 5×5 매트릭스 25케이스 검증
- CANCELLED 후 재고 복원
