# 주문 관리 - 재고 연동 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 재고 연동  
**SDLC 단계:** 구현  
**변경 요점:** 재고 부족 거부 + DELETE 복원 + StockHistory 적재 + 락 적용.

## 1. 구현 범위

OrderService의 create/updateStatus/delete가 [[재고관리]] adjustStock을 호출하도록 통합. 동시성 보호.

## 2. 구현 항목 체크리스트

- [ ] OrderService.create: product.quantity < order.quantity → 409
- [ ] 재고 부족 검증 없음.
- [ ] adjustStock(-qty, ORDER) 호출 (StockHistory 자동 적재)
- [ ] 등록 후 product.quantity -= order.quantity
- [ ] updateStatus CANCELLED 분기 → adjustStock(+qty, CANCEL)
- [ ] CANCELLED 후 += 복원
- [ ] delete 분기 → status가 CANCELLED 아니면 adjustStock(+qty, CANCEL)
- [ ] 비관적 락 또는 낙관적 락 적용
- [ ] 통합 테스트(동시 등록 100건 + 재고 1건 시나리오)

## 3. 적용 기술

- @Transactional + @Lock
- 트랜잭션 내 호출
- StockHistory 자동 적재 ([[재고관리]] 메서드 활용)

## 4. 단계별 작업 순서

1. adjustStock 메서드 인터페이스 확정 
2. Order 흐름에서 호출 
3. 락 적용 
4. 동시성 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 락 경합 증가로 처리량 저하 | 부하 테스트 후 락 종류 재검토 |

## 6. 검증 포인트

- 음수 결과 시 트랜잭션 롤백
- StockHistory 누락 0건
- DELETE 시 복원 정확성
