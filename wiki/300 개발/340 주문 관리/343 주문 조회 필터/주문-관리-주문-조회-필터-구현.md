# 주문 관리 - 주문 조회 필터 - 구현

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 주문 조회 필터  
**SDLC 단계:** 구현  
**변경 요점 (vs 1차):** Specification 기반 통합 검색, 페이지네이션, 인덱스 추가.

## 1. 구현 범위

`/api/orders/search` 엔드포인트를 신설하고, 다중 조건을 Specification으로 조립.

## 2. 구현 항목 체크리스트

- [ ] OrderRepository extends JpaSpecificationExecutor<Order>
- [ ] OrderSpecs: customer, status, dateBetween, employee
- [ ] OrderService.search(criteria, pageable)
- [ ] OrderController.search 핸들러 (@RequestParam Optional ...)
- [ ] size 클램프(1~100), 정렬 기본 orderDate DESC
- [ ] DDL: 인덱스 3종 추가
- [ ] 1차 경로(`/customer/{}`, `/status/{}`) deprecated 헤더
- [ ] 통합 테스트
- [ ] findByCustomerId(Long customerId)
- [ ] findByStatus(OrderStatus status)
- [ ] GET /api/orders/customer/{customerId}
- [ ] GET /api/orders/status/{status}
- [ ] enum 변환 실패 → 400
- [ ] 단위 테스트

## 3. 적용 기술

- Spring Data JPA Specification
- Pageable
- DB 복합 인덱스

## 4. 단계별 작업 순서

1. Specification 빌더 
2. Service/Controller 
3. 인덱스 
4. deprecation 처리 
5. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 잘못된 인덱스로 성능 저하 | EXPLAIN 확인 후 인덱스 조정 |

## 6. 검증 포인트

- 다중 조건 결합 시 결과 정확
- 페이지 메타(totalPages 등) 정확
- enum 변환 실패 시 400 응답 확인
