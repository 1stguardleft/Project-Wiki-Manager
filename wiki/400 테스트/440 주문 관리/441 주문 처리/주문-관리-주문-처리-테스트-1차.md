# 주문 관리 - 주문 처리 - 테스트

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 주문 처리  
**SDLC 단계:** 테스트  
**변경 요점 (vs 1차):** employee 필수, 재고 부족 거부, DELETE 복원, memo 검증.

## 1. 테스트 범위

CRUD + 신규 정책 (employee/재고/메모/DELETE 복원).

## 2. 정상 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| ORD-N1 | 등록 (정상) | 재고 충분, employee 존재 | POST | 201 |
| ORD-N2 | DELETE 복원 | 재고 차감 5 | DELETE | quantity +5 복원 |
| ORD-N3 | memo 입력 | memo="VIP 고객" | POST | 응답에 memo 포함 |
| ORD-N4 | 삭제 | id 보유 | DELETE | 204 |

## 3. 경계·예외 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| ORD-E1 | 재고 부족 | quantity=2, 주문 수량 3 | POST | 409 INSUFFICIENT_STOCK, 재고 변동 없음 |
| ORD-E2 | employee 누락 | - | POST | 400 |
| ORD-E3 | employee 미존재 | employeeId=999 | POST | 404 |
| ORD-E4 | memo 길이 초과 | 201자 | POST | 400 |
| ORD-E5 | CANCELLED 주문 DELETE | 이미 CANCELLED | DELETE | 204, 재고 추가 복원 없음 |
| ORD-E6 | DELETE 후 재고 미복원 | 등록 후 삭제 | product.quantity 확인 | 변동 없음 |

## 4. 통합·회귀

- 1차 등록 케이스가 (employee 누락) → 400으로 명확 안내
- 동시 등록 100건 vs 재고 50 → 50건 성공·50건 409
- 등록 시 재고 차감 + totalAmount 정확성 동시 확인
- 다수 동시 등록 시 트랜잭션 격리 동작

## 5. 합격 기준

- 정상/예외 TC 100%, 응답 1초 이내
- 동시성 시나리오에서 재고 음수 0건
