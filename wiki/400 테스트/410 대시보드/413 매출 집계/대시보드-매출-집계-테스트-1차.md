# 대시보드 - 매출 집계 - 테스트

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 대시보드 / 매출 집계  
**SDLC 단계:** 테스트  
**변경 요점 (vs 1차):** DELIVERED 필터, 기간 필터, 월 매출 분리 검증.

## 1. 테스트 범위

`GET /api/dashboard/sales` 호출 시 합산 정확성, 기간/상태 필터 동작, 월 경계 처리를 검증한다.

## 2. 정상 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| SALES-N1 | DELIVERED 합계 | DELIVERED 3건(만/2만/3만), PENDING 1건(5만) | GET /sales | totalSales=60000 |
| SALES-N2 | 기간 필터 | 2026-01에 1만, 2026-02에 2만 DELIVERED | /sales?from=2026-02-01&to=2026-02-28 | totalSales=20000 |
| SALES-N3 | 월 분리 | 이번 달 DELIVERED 5만, 지난 달 3만 | 기본 호출 | currentMonthSales=50000, previousMonthSales=30000 |
| SALES-N4 | 주문 추가/삭제 후 합계 갱신 확인 | DELIVERED 2건(1만, 2만) | 주문 추가 후 GET /sales | totalSales=30000 |
| SALES-N5 | 다른 대시보드 API와 동시 호출 시 정상 응답 | DELIVERED 3건(1만, 2만, 3만) | GET /sales 및 다른 API 호출 | 모든 API 정상 응답 |

## 3. 경계·예외 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| SALES-E1 | from > to | - | /sales?from=2026-03-01&to=2026-02-01 | 400 (INVALID_PERIOD) |
| SALES-E2 | 기간 내 0건 | 해당 기간 DELIVERED 없음 | /sales?from=...&to=... | totalSales=0 |
| SALES-E3 | CANCELLED만 존재 | CANCELLED 10만원 1건 | 동일 | totalSales=0 |

## 4. 통합·회귀

- 주문이 PENDING→DELIVERED로 전이될 때 합계가 즉시 반영되는지
- 월말 자정에 currentMonthSales / previousMonthSales 경계가 정확히 이동하는지
- DB 합계와 일치, 응답 1.5초 이내

## 5. 합격 기준

- 상태/기간 필터 정확
- 0건 시 0 반환 (null 금지)
- 응답 1.5초 이내
