# 고객 관리 - 고객 변경 이력 - 테스트

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 고객 관리 / 고객 변경 이력  
**SDLC 단계:** 테스트  
**변경 요점 (vs 1차):** 변경 감지 + 이력 적재 검증.

## 1. 테스트 범위

수정 시 이력 row 생성 정확성, 변경 없는 필드의 row 미생성, 트랜잭션 일관성. 수정 시 `updated_at`이 갱신되는지만 확인 (이력 보존은 범위 외).

## 2. 정상 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| HIST-N1 | 단일 필드 변경 | phone 변경 | PUT | History 1건(field=phone) |
| HIST-N2 | 다중 필드 변경 | name, phone 변경 | PUT | History 2건 |
| HIST-N3 | 변경 없음 | 동일 값으로 PUT | PUT | History 0건 |
| HIST-N4 | 이력 조회 | 변경 3회 | GET /history | 시각 내림차순으로 응답 |
| HIST-N5 | updated_at 갱신 | 필드 변경 | PUT | updated_at이 현재 시각으로 갱신 |

## 3. 경계·예외 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| HIST-E1 | 트랜잭션 롤백 | 이력 insert 강제 실패 | PUT | 수정도 롤백, 데이터 원상 |
| HIST-E2 | 등록·삭제 시 적재 | - | POST/DELETE | History 0건(수정만 대상) |

## 4. 통합·회귀

- 수정 후 즉시 GET /history에 반영
- 5년 이상 이력 보존 (보관 정책 적용 후)

## 5. 합격 기준

- 이력 누락 0건, 잘못된 row 0건
- 추가 응답 지연 100ms 이내
- 변경 전 값 보존 미요구
