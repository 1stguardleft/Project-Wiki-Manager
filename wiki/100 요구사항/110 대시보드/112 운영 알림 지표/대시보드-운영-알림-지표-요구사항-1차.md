# 대시보드 - 운영 알림 지표 - 요구사항

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 대시보드 / 운영 알림 지표  
**SDLC 단계:** 요구사항  
**변경 요점 (vs 1차):** 재고 부족 임계값을 query param으로 외부화, 신규 "장기 미처리 주문" 지표 추가.

## 1. 개요

운영자가 즉시 조치해야 할 항목(접수 대기 주문, 재고 부족 상품, 장기 미처리 주문)의 건수를 단일 API로 반환한다.

## 2. 사용자 시나리오

- 운영자가 `threshold=20`으로 호출해 "재고 20개 미만" 상품을 추적한다.
- 매니저가 24시간 이상 처리되지 않은 주문을 알림으로 확인한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 알림-01 | 접수 대기 주문 수 | PENDING 주문 건수 | 필수 |
| 알림-02 | 재고 부족 상품 수 | quantity < threshold (기본 10) | 필수 |
| 알림-03 | 임계값 파라미터 | `?threshold=N` 으로 조정 가능 | 필수 |
| 알림-04 | 장기 미처리 주문 수 | 24시간 이상 PENDING 상태 (신규) | 권장 |

## 4. 응답 정보

| 항목 | 형식 | 설명 |
|---|---|---|
| pendingOrders | 정수 | PENDING 주문 수 |
| lowStockItems | 정수 | quantity < threshold 상품 수 |
| staleOrders | 정수 | 24시간 이상 PENDING 주문 수 (2차 신규) |
| threshold | 정수 | 적용된 임계값 |

## 5. 업무 규칙

- threshold 기본값 10, 허용 범위 1~1000. 재고 부족 임계값은 10으로 고정한다(1차 범위 내 변경 불가).
- 잘못된 threshold(음수·문자) 입력 시 기본값으로 폴백.
- 취소된 주문은 접수 대기 카운트에 포함하지 않는다.

## 6. 비기능 요구사항

- 응답 시간 1초 이내. threshold 변경 호출도 동일 성능.
- 화면이 5분 주기로 새로 고침되어도 부하 문제가 없어야 함.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| threshold 범위 초과 | 1 또는 1000으로 클램프 |
| 일부 지표 조회 실패 | 해당 지표만 -1, 나머지 정상 |
