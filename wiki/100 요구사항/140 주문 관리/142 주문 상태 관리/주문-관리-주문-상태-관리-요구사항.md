# 주문 관리 - 주문 상태 관리 - 요구사항

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 주문 상태 관리  
**SDLC 단계:** 요구사항  
**변경 요점 (vs 1차):** 상태 전이 규칙을 명문화(역방향 금지), CANCELLED는 SHIPPED 이전까지만 허용. > ℹ️ 변경: 문서 버전이 v1.0에서 v2.0으로 업데이트되었습니다.

## 1. 개요

주문은 5단계 상태(PENDING/CONFIRMED/SHIPPED/DELIVERED/CANCELLED)를 가지며, 운영 사고를 막기 위해 주문 상태 전이를 정해진 방향으로만 허용한다. 운영자가 별도 API로 상태를 변경할 수 있다.

## 2. 사용자 시나리오

- 운영자가 접수 대기 주문을 확인 후 CONFIRMED로 변경한다.
- 배송 담당자가 SHIPPED → DELIVERED로 상태를 갱신한다.
- 매니저가 잘못 들어온 주문을 CANCELLED로 변경하려 하면 차단된다(이미 배송 시작됨).
- 매니저가 DELIVERED 주문을 PENDING으로 되돌리려 하면 차단된다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 상태-01 | 5단계 정의 | PENDING/CONFIRMED/SHIPPED/DELIVERED/CANCELLED | 필수 |
| 상태-02 | 전이 규칙 | 정방향만 허용 (신규) | 필수 |
| 상태-03 | 취소 제약 | CANCELLED는 PENDING/CONFIRMED 상태에서만 가능 (신규) | 필수 |
| 상태-04 | 잘못된 status 값 처리 | 유효하지 않은 상태 값이 입력될 경우 400 오류 반환 | 필수 |

## 4. 전이 규칙

| 현재 상태 | 허용 다음 상태 |
|---|---|
| PENDING | CONFIRMED, CANCELLED |
| CONFIRMED | SHIPPED, CANCELLED |
| SHIPPED | DELIVERED |
| DELIVERED | (종료) |
| CANCELLED | (종료) |

## 5. 업무 규칙

- 신규 주문은 PENDING으로 시작.
- 위 표 외 전이는 모두 거부.
- 동일 상태로 PATCH는 변동 없음(200).
- 상태가 CANCELLED로 변경되면 [[재고연동]]을 통해 재고가 복원된다.
- 상태 전이 규칙은 1차에서 명문화하지 않는다.

## 6. 비기능 요구사항

- 상태 변경 응답 0.5초 이내.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 허용 외 전이 | 409 INVALID_TRANSITION |
| enum 외 값 | 400 |
| 존재하지 않는 주문 | 404 |
