# 주문 관리 - 주문 처리 - 요구사항

**문서 버전:** v2.0  
**도메인 / 서브도메인:** 주문 관리 / 주문 처리  
**SDLC 단계:** 요구사항  
**변경 요점 (vs 1차):** 담당 직원(employee_id) 추가, 주문 메모(memo) 필드 추가, 재고 부족 시 등록 거부. > ℹ️ 변경: 문서 버전이 v1.0에서 v2.0으로 업데이트되었습니다.

## 1. 개요

운영자가 고객의 주문을 등록·조회·삭제할 수 있어야 한다. 주문은 고객과 상품을 연결하는 핵심 트랜잭션 데이터다. 주문에 **누가 등록했는지(담당 직원)**와 메모를 기록할 수 있게 한다. 재고 부족 시 주문 등록을 명시적으로 차단한다.

## 2. 사용자 시나리오

- 영업 담당자가 자기 ID를 employee로 설정한 채 주문을 등록한다.
- 매니저가 직원별 주문 실적을 확인한다.
- 운영자가 재고 부족 상품으로 주문을 시도하면 즉시 차단된다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 주문-01 | 등록 | 신규 주문 등록 | 필수 |
| 주문-02 | 목록 | 전체 조회 | 필수 |
| 주문-03 | 상세 | 단건 조회 | 필수 |
| 주문-04 | 삭제 | 주문 제거 | 필수 |
| 주문-05 | 담당 직원 기록 | employee_id 필수 (신규) | 필수 |
| 주문-06 | 메모 | 운영자 메모 (선택, 신규) | 권장 |
| 주문-07 | 재고 부족 거부 | 등록 시 재고 부족이면 차단 (신규) | 필수 |

## 4. 관리 정보

| 항목 | 필수 | 형식 | 설명 |
|---|---|---|---|
| customer | 필수 | FK | 주문 고객 |
| product | 필수 | FK | 주문 상품 |
| quantity | 필수 | 정수 ≥ 1 | 수량 |
| totalAmount | 자동 | 정수(원) | 자동 산출 |
| status | 자동 | enum | 초기 PENDING |
| employee | 필수 | FK | 담당 직원 (신규) |
| memo | 선택 | 200자 이내 | 운영자 메모 (신규) |

## 5. 업무 규칙

- customer/product 누락 시 등록 불가.
- quantity는 1 이상.
- totalAmount는 가격 × 수량으로 자동 산출 ([[금액계산]] 참고).
- 등록 시 [[재고연동]]을 통해 재고가 자동 차감된다.
- 1차에서는 담당 직원 개념이 없음. > ℹ️ 변경: 담당 직원 개념이 추가되었습니다.
- 등록 시 재고 부족(quantity < 수량) → 거부.
- 삭제 시 재고 복원 (1차 미복원에서 변경).
- 메모는 200자 이내.

## 6. 비기능 요구사항

- 등록 응답 1초 이내. 재고 검증 추가 지연 50ms 이내.
- 조회 응답 1초 이내(1만 건 기준).

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 재고 부족 | 409 INSUFFICIENT_STOCK |
| 존재하지 않는 customer/product | 404 |
| 존재하지 않는 주문 조회/삭제 | 404 |
| 존재하지 않는 employee | 404 |
| quantity < 1 | 400 |
| 메모 길이 초과 | 400 |
