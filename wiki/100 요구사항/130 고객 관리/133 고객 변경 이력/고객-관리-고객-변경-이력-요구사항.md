# 고객 관리 - 고객 변경 이력 - 요구사항

**문서 버전:** v1.0  
**도메인 / 서브도메인:** 고객 관리 / 고객 변경 이력  
**SDLC 단계:** 요구사항  

## 1. 개요

감사·민원 대응을 위해 고객 정보의 **모든 수정 이력**을 보존한다. 어떤 컬럼이 무엇에서 무엇으로 바뀌었는지 추적 가능해야 한다.  
> ℹ️ 변경: 고객 정보의 변경 이력을 보존하는 것으로 수정됨.  
> ℹ️ 추가: 1차 범위에서는 고객 정보의 변경 이력을 별도 보존하지 않는다. 수정 시 최신 값으로 덮어쓴다. 운영자가 고객 정보를 수정하면 즉시 반영되며, 과거 값은 시스템에서 조회할 수 없다.

## 2. 사용자 시나리오

- 매니저가 특정 고객의 전화번호가 언제, 누구에 의해, 어떻게 바뀌었는지 확인한다.
- 감사 담당자가 특정 기간 변경 이력 전체를 조회한다.  
> ℹ️ 변경: 사용자 시나리오가 구체화됨.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 이력-01 | 자동 적재 | 고객 수정 시 변경 이력 자동 적재 | 필수 |
| 이력-02 | 고객별 이력 조회 | `GET /api/customers/{id}/history` | 필수 |
| 이력-03 | 변경 필드 단위 기록 | 어떤 필드가 어떻게 바뀌었는지 | 필수 |  
> ℹ️ 변경: 기능 요구사항이 추가되고 우선순위가 변경됨.  
> ℹ️ 추가: 변경 이력 테이블 없음.  
> ℹ️ 추가: `updated_at` 컬럼만 최신 수정 시각 저장.

## 4. 관리 정보 (CustomerHistory)

| 항목 | 형식 | 설명 |
|---|---|---|
| customer_id | FK | 대상 고객 |
| field | 문자열 | 변경된 컬럼명 |
| oldValue / newValue | 문자열 | 변경 전/후 값 |
| changedAt | timestamp | 변경 시각 |
| changedBy | 문자열 | 변경자(운영자 ID, 1차에는 시스템 기본값) |  
> ℹ️ 변경: 관리 정보 항목이 추가됨.

## 5. 업무 규칙

- 등록·삭제는 이력 적재 대상 아님(수정만).
- 동일 트랜잭션에서 여러 필드 변경 시 필드별 row 적재.
- 보존 기간 5년(추후 정책 정의).  
> ℹ️ 변경: 업무 규칙이 추가되고 수정됨.  
> ℹ️ 추가: (보류) | 변경 이력 미보존 | 후순위

## 6. 비기능 요구사항

- 수정으로 인한 응답 추가 지연 100ms 이내.  
> ℹ️ 변경: 비기능 요구사항이 추가됨.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 변경 사항 없음 | 이력 적재 생략 |
| 이력 적재 실패 | 트랜잭션 롤백, 수정도 취소 |  
> ℹ️ 변경: 예외 처리 항목이 추가됨.
