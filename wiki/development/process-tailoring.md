# 프로세스 테일러링 기준

## 문서 목적

이 문서는 표준 개발 프로세스를 현재 프로젝트 상황에 맞게 조정하기 위한 기준을 정의한다.
프로젝트 규모, 팀 구성, 일정 제약, 외부 의존성을 고려하여 어떤 활동을 유지하고 어떤 활동을 축소하거나 생략할지 합의하는 데 목적이 있다.

## 적용 범위

- 신규 웹 서비스 개발 프로젝트
- 3개월 이내의 단기 구축 과제
- 내부 개발자 4명 이하의 소규모 팀
- 외부 솔루션 연동이 포함된 프로젝트

## 프로젝트 특성별 조정 기준

## 산출물 테일러링 표

| 산출물 | 기본 정책 | 축소 가능 조건 | 생략 가능 여부 |
|------|------|------|------|
| 프로젝트 계획서 | 작성 | 소규모 프로젝트는 간략 버전 허용 | 불가 |
| 요구사항 정의서 | 작성 | 사용자 스토리 기반 간략화 가능 | 불가 |
| 상세 설계서 | 작성 | 핵심 기능 중심으로 축소 가능 | 조건부 가능 |
| 테스트 케이스 | 작성 | 핵심 시나리오 우선 작성 | 조건부 가능 |
| 운영 이관 문서 | 작성 | 분량 축소 가능 | 불가 |
| 주간 보고서 | 작성 | 보드 캡처 또는 요약 메모 대체 가능 | 가능 |

## 역할별 책임

## 운영 전환 기준

운영 전환 전에는 아래 항목을 모두 확인한다.

- 배포 절차 문서 최신화
- 장애 대응 연락망 공유
- 운영 계정 및 권한 확인
- 로그 확인 방법 문서화
- 백업 및 복구 절차 확인

## 변경 관리

프로젝트 진행 중 다음 상황이 발생하면 테일러링 기준을 다시 검토한다.

- 일정 20% 이상 변동
- 외부 연동 시스템 추가
- 인력 구성 변경
- 보안 요구사항 추가
- 운영 범위 확대

## 승인 기록

- 초안 작성: PM
- 기술 검토: 리드 개발자
- 최종 승인: 프로젝트 책임자
