# 상품 관리 - SKU 식별 - 요구사항 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 상품 관리 / SKU 식별
**SDLC 단계:** 요구사항
**변경 요점 (vs 1차):** SKU unique 제약, 형식 검증(영문 대문자/숫자/하이픈, 3~30자), SKU로 단건 조회 API 추가.

## 1. 개요

SKU를 운영 식별자로 표준화한다. 중복·오타·형식 혼란을 막기 위해 unique 제약과 정규식 검증을 적용하고, SKU로 상품을 빠르게 조회하는 API를 제공한다.

## 2. 사용자 시나리오

- 운영자가 신규 등록 시 잘못된 SKU(`milk1L!`, 한글, 너무 짧음 등)는 즉시 거부된다.
- POS 시스템이 바코드에서 추출한 SKU로 상품을 조회한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| SKU-01 | SKU 입력 | 등록·수정 시 SKU 입력 | 필수 |
| SKU-02 | SKU 형식 검증 | 정규식 `^[A-Z0-9-]{3,30}$` | 필수 |
| SKU-03 | SKU unique 검증 | 시스템 전체 unique | 필수 |
| SKU-04 | SKU로 상품 조회 | `GET /api/products/sku/{sku}` (신규) | 권장 |

## 4. 관리 정보

| 항목 | 필수 | 형식 | 설명 |
|---|---|---|---|
| sku | 필수 | 영문대문자/숫자/하이픈, 3~30자 | 식별자 |

## 5. 업무 규칙

- SKU는 unique.
- 형식 미준수 → 400.
- SKU 변경은 허용 (단, 변경 후에도 unique·형식 유효).

## 6. 비기능 요구사항

- SKU로 단건 조회 응답 200ms 이내(인덱스 사용).

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 형식 위반 | 400, errorCode = INVALID_SKU_FORMAT |
| 중복 | 409, errorCode = DUPLICATE_SKU |
| SKU 미존재 조회 | 404 |
