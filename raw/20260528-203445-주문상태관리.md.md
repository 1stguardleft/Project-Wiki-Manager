# 주문 관리 - 주문 상태 관리 - 설계 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 주문 관리 / 주문 상태 관리
**SDLC 단계:** 설계
**변경 요점 (vs 1차):** 전이 검증 메서드 신설, 허용 전이 매트릭스 적용.

## 1. 설계 개요

상태 변경 시 `OrderStatus.isAllowedTransition(from, to)`로 검증해 정의된 전이만 허용한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Enum/Service | OrderStatus / OrderService | 전이 매트릭스 + 검증 |
| Controller | OrderController | PATCH 핸들러 |

## 3. 전이 매트릭스 (코드 상수)

| from | to (허용) |
|---|---|
| PENDING | CONFIRMED, CANCELLED |
| CONFIRMED | SHIPPED, CANCELLED |
| SHIPPED | DELIVERED |
| DELIVERED | (없음) |
| CANCELLED | (없음) |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| PATCH | /api/orders/{id}/status | 상태 변경 (검증 적용) |

## 5. 처리 흐름

1. 입력 status 검증
2. Order 조회 → current → isAllowed(current, target) 검사
3. 허용 시 변경 + (CANCELLED면) 재고 복원
4. 미허용 → 409 INVALID_TRANSITION

## 6. 설계 규칙

- 동일 상태 PATCH는 변동 없음(200).
- 매트릭스는 enum/상수로 관리(테스트 용이).
