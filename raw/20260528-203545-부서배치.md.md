# 직원 관리 - 부서 배치 - 설계 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 직원 관리 / 부서 배치
**SDLC 단계:** 설계
**변경 요점 (vs 1차):** departmentId nullable, unassigned 조회 API, EmployeeDepartmentHistory 적재.

## 1. 설계 개요

Employee.department_id를 nullable로 변경하고, 부서 변경 시 EmployeeDepartmentHistory 엔티티에 이력을 적재한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | EmployeeController | 부서별/미배치 조회 |
| Service | EmployeeService | 변경 감지 + 이력 적재 |
| Entity | EmployeeDepartmentHistory | 신규 |
| Repository | EmployeeDepartmentHistoryRepository | 이력 조회 |

## 3. 데이터 모델

**Employee (변경)**

| 컬럼 | 타입 | 제약 |
|---|---|---|
| department_id | bigint | FK, nullable |

**EmployeeDepartmentHistory (신규)**

| 컬럼 | 타입 | 제약 |
|---|---|---|
| employee_id | FK | NOT NULL |
| from_dept_id | FK | nullable |
| to_dept_id | FK | nullable |
| changed_at | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/employees/department/{deptId} | 부서별 |
| GET | /api/employees/unassigned | 미배치 (신규) |
| GET | /api/employees/{id}/department-history | 부서 변경 이력 (신규) |

## 5. 처리 흐름

- 등록: departmentId 없으면 unassigned로 저장
- 부서 변경: before/after 비교 → 변경 시 이력 row insert

## 6. 설계 규칙

- DB 제약 NULL 허용.
- 이력은 트랜잭션 내 적재.
