# 직원 관리 - 부서 배치 - 요구사항 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 직원 관리 / 부서 배치
**SDLC 단계:** 요구사항
**변경 요점 (vs 1차):** departmentId nullable 허용(미배치 직원 등록 가능), 부서 변경 시 이력 적재.

## 1. 개요

신입 등록 시점에 아직 부서가 정해지지 않은 케이스를 지원하기 위해 departmentId를 nullable로 완화한다. 부서 변경은 향후 인사 감사용으로 이력에 적재한다.

## 2. 사용자 시나리오

- 인사 담당자가 부서 미정 상태에서 신입을 먼저 등록한다.
- 매니저가 직원의 부서를 변경하면 변경 이력이 자동 적재된다.
- 미배치(unassigned) 직원 목록을 별도 API로 조회한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 배치-01 | 부서 선택적 | 등록 시 departmentId 선택 (신규) | 필수 |
| 배치-02 | 부서별 직원 조회 | 1차 동일 | 필수 |
| 배치-03 | 미배치 직원 조회 | `GET /api/employees/unassigned` (신규) | 권장 |
| 배치-04 | 부서 변경 이력 | 부서 변경 시 이력 row 적재 (신규) | 권장 |

## 4. 관리 정보 (Employee + EmployeeDepartmentHistory)

| 항목 | 형식 | 설명 |
|---|---|---|
| departmentId | FK, nullable | 소속 부서 |
| (이력) employee_id / from_dept / to_dept / changed_at | - | 부서 변경 이력 |

## 5. 업무 규칙

- departmentId nullable.
- 변경(null → A, A → B) 모두 이력 row 적재.
- 미배치 상태가 30일 이상 지속되면 경고 알림(권장, 추후).

## 6. 비기능 요구사항

- 부서별 조회 응답 1초 이내.
