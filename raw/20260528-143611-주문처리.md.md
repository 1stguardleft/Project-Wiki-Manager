# 주문 관리 - 주문 처리 - 요구사항 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 주문 관리 / 주문 처리
**SDLC 단계:** 요구사항

## 1. 개요

운영자가 고객의 주문을 등록·조회·삭제할 수 있어야 한다. 주문은 고객과 상품을 연결하는 핵심 트랜잭션 데이터다.

## 2. 사용자 시나리오

- 영업 담당자가 고객/상품/수량을 입력해 주문을 등록한다.
- 매니저가 전체 주문 목록을 확인한다.
- 운영자가 잘못 등록된 주문을 삭제한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 주문-01 | 주문 등록 | 신규 주문을 등록 | 필수 |
| 주문-02 | 주문 목록 조회 | 전체 주문 목록 | 필수 |
| 주문-03 | 주문 상세 조회 | 단건 조회 | 필수 |
| 주문-04 | 주문 삭제 | 주문 제거 | 필수 |

## 4. 관리 정보

| 항목 | 필수 | 형식 | 설명 |
|---|---|---|---|
| customer | 필수 | FK | 주문 고객 |
| product | 필수 | FK | 주문 상품 |
| quantity | 필수 | 정수 ≥ 1 | 수량 |
| totalAmount | 자동 | 정수(원) | 자동 산출 |
| status | 자동 | 문자열 | 초기 PENDING |
| orderDate | 자동 | timestamp | 등록 시각 |

## 5. 업무 규칙

- customer/product 누락 시 등록 불가.
- quantity는 1 이상.
- totalAmount는 가격 × 수량으로 자동 산출 ([[금액계산]] 참고).
- 등록 시 [[재고연동]]을 통해 재고가 자동 차감된다.
- 1차에서는 담당 직원 개념이 없음.

## 6. 비기능 요구사항

- 등록 응답 1초 이내.
- 조회 응답 1초 이내(1만 건 기준).

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 존재하지 않는 customer/product | 404 |
| quantity < 1 | 400 |
| 존재하지 않는 주문 조회/삭제 | 404 |
