# 공통/인프라 - 전역 예외 처리 - 구현 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 공통/인프라 / 전역 예외 처리
**SDLC 단계:** 구현
**변경 요점 (vs 1차):** ErrorCode enum, BusinessException, 핸들러 4종 분리.

## 1. 구현 범위

ErrorCode enum, BusinessException 도입, GlobalExceptionHandler에 핸들러 4종 추가.

## 2. 구현 항목 체크리스트

- [ ] `enum ErrorCode { VALIDATION_FAILED, NOT_FOUND, DUPLICATE_SKU, ... }` 카탈로그
- [ ] `class BusinessException(ErrorCode code, String message) extends RuntimeException`
- [ ] @ExceptionHandler 4종 추가 (Validation/NotFound/Conflict/Unknown)
- [ ] DataIntegrityViolationException → 제약명 분석 → DUPLICATE_*
- [ ] 도메인 Service의 throw를 BusinessException으로 통일
- [ ] 로그 형식 표준화 (errorCode 포함)
- [ ] 통합 테스트

## 3. 적용 기술

- Java enum
- Spring @ControllerAdvice
- SLF4J + MDC(errorCode)

## 4. 단계별 작업 순서

1. ErrorCode/BusinessException → 2. 핸들러 4종 → 3. 도메인 throw 통일 → 4. 로그 표준 → 5. 통합 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 1차 일괄 500 처리 코드 누락 | Exception 핸들러는 마지막 catch-all로 유지 |
| 제약명 분석이 DB 종류에 따라 다름 | 제약명 표준 정의 + 테스트로 보장 |

## 6. 검증 포인트

- 각 예외 타입별 코드/메시지 정확
- 모든 도메인이 BusinessException 또는 표준 예외 사용
