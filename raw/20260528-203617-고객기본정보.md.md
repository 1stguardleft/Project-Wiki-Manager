# 고객 관리 - 고객 기본정보 - 구현 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 고객 관리 / 고객 기본정보
**SDLC 단계:** 구현
**변경 요점 (vs 1차):** email UNIQUE 마이그레이션, 활성 주문 검사, 예외 매핑.

## 1. 구현 범위

Customer 엔티티에 UNIQUE 제약 추가, Service에 사전 검증 / 삭제 차단 추가.

## 2. 구현 항목 체크리스트

- [ ] DDL: `ALTER TABLE customer ADD CONSTRAINT uk_customer_email UNIQUE(email)`
- [ ] 마이그레이션: 기존 중복 이메일 정리 스크립트
- [ ] `existsByEmail` derived query
- [ ] `OrderRepository.existsByCustomerIdAndStatusIn(...)` 활용
- [ ] 삭제 메서드에 활성 주문 검사
- [ ] [[전역예외처리]]에 UNIQUE 위반 → DUPLICATE_EMAIL 매핑
- [ ] 통합 테스트

## 3. 적용 기술

- Bean Validation (`@Email`)
- JPA + 마이그레이션 도구

## 4. 단계별 작업 순서

1. 중복 정리 보고서 → 2. 정리 후 UNIQUE 적용 → 3. Service 사전 체크 → 4. 활성 주문 검사 → 5. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 기존 중복 이메일 다수 | 운영자 검토 후 일괄 정리 |
| 활성 주문 검사 누락 | 단위 테스트로 보장 |

## 6. 검증 포인트

- 중복 등록 → 409
- 활성 주문 보유 삭제 → 409
