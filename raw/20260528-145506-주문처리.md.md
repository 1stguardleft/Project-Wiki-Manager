# 주문 관리 - 주문 처리 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 주문 관리 / 주문 처리
**SDLC 단계:** 설계

## 1. 설계 개요

주문 CRUD를 Controller → Service → Repository 3계층으로 구현. 등록 시 [[재고연동]]·[[금액계산]] 흐름을 한 트랜잭션에서 처리한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | OrderController | 등록/조회/삭제 |
| Service | OrderService | 비즈니스 로직 + 트랜잭션 |
| Entity | Order | 주문 모델 |
| Repository | OrderRepository | JPA Repository |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint | PK |
| customer_id | FK | NOT NULL |
| product_id | FK | NOT NULL |
| quantity | int | NOT NULL, ≥ 1 |
| total_amount | bigint | NOT NULL |
| status | varchar(20) | NOT NULL, default PENDING |
| order_date | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/orders | 등록 |
| GET | /api/orders | 전체 |
| GET | /api/orders/{id} | 상세 |
| DELETE | /api/orders/{id} | 삭제 |

## 5. 처리 흐름

- 등록: customer/product 존재 검증 → totalAmount 계산 → 재고 차감 → save → 201
- 삭제: 존재 검증 → delete → 204 (재고 복원 없음)

## 6. 설계 규칙

- 등록은 `@Transactional` 보호.
- DELETE 시 재고 복원하지 않음.
- 1차에는 직원·메모 등 부가 컬럼 없음.
