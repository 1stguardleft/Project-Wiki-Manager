# 주문 관리 - 주문 상태 관리 - 요구사항 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 주문 관리 / 주문 상태 관리
**SDLC 단계:** 요구사항

## 1. 개요

주문은 5단계 상태(PENDING/CONFIRMED/SHIPPED/DELIVERED/CANCELLED)를 가지며, 운영자가 별도 API로 상태를 변경할 수 있다.

## 2. 사용자 시나리오

- 운영자가 접수 대기 주문을 확인 후 CONFIRMED로 변경한다.
- 배송 담당자가 SHIPPED → DELIVERED로 상태를 갱신한다.
- 매니저가 잘못 들어온 주문을 CANCELLED로 변경한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 상태-01 | 5단계 정의 | PENDING/CONFIRMED/SHIPPED/DELIVERED/CANCELLED | 필수 |
| 상태-02 | 상태 변경 | 별도 API로 임의 상태로 변경 가능 | 필수 |

## 4. 관리 정보

| 항목 | 형식 | 설명 |
|---|---|---|
| status | 문자열 | 5개 enum 중 하나 |

## 5. 업무 규칙

- 신규 주문은 PENDING으로 시작.
- **상태 전이 규칙은 1차에서 명문화하지 않는다**(임의 전이 허용).
- 상태가 CANCELLED로 변경되면 [[재고연동]]을 통해 재고가 복원된다.

## 6. 비기능 요구사항

- 상태 변경 응답 0.5초 이내.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 잘못된 status 값 | 400 |
| 존재하지 않는 주문 | 404 |
