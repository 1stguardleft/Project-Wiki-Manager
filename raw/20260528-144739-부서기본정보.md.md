# 부서 관리 - 부서 기본정보 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 부서 관리 / 부서 기본정보
**SDLC 단계:** 설계

## 1. 설계 개요

부서 CRUD를 3계층으로 구현. name은 UNIQUE 제약.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | DepartmentController | CRUD |
| Service | DepartmentService | UNIQUE 사전 체크 |
| Entity | Department | 모델 |
| Repository | DepartmentRepository | existsByName |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint | PK |
| name | varchar(80) | NOT NULL, UNIQUE |
| description | varchar(500) | nullable |
| created_at | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/departments | 등록 |
| GET | /api/departments | 목록 |
| GET | /api/departments/{id} | 상세 |
| PUT | /api/departments/{id} | 수정 |
| DELETE | /api/departments/{id} | 삭제 |

## 5. 처리 흐름

- 등록: existsByName → save → 201 (UNIQUE 위반 시 409)
- 삭제: 직원 검사 없이 delete → 204

## 6. 설계 규칙

- DB UNIQUE + Service 사전 체크.
- 1차에서 부서장 컬럼 없음.
