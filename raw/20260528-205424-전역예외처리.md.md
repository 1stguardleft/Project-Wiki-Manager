# 공통/인프라 - 전역 예외 처리 - 테스트 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 공통/인프라 / 전역 예외 처리
**SDLC 단계:** 테스트
**변경 요점 (vs 1차):** errorCode 매핑·BusinessException 검증.

## 1. 테스트 범위

각 예외 → HTTP/errorCode 매핑, BusinessException 흐름.

## 2. 정상 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| EXC-N1 | Validation | 필수 누락 | POST | 400 / VALIDATION_FAILED |
| EXC-N2 | Not Found | id=999 | GET | 404 / NOT_FOUND |
| EXC-N3 | Duplicate (UNIQUE) | 중복 등록 | POST | 409 / DUPLICATE_* |
| EXC-N4 | BusinessException | 도메인 throw | API | 핸들러가 잡고 errorCode 반환 |

## 3. 경계·예외 시나리오

| TC-ID | 시나리오 | 전제 | 실행 | 기대 결과 |
|---|---|---|---|---|
| EXC-E1 | Unknown | NPE 강제 | API | 500 / UNKNOWN_ERROR |
| EXC-E2 | 핸들러 내부 추가 예외 | 직렬화 실패 | API | 폴백 500 / UNKNOWN_ERROR |

## 4. 통합·회귀

- 모든 도메인의 실제 예외가 정해진 errorCode를 반환하는지 매핑 표 검증

## 5. 합격 기준

- errorCode 표 100% 일치
- 모든 응답이 [[공통API응답]] 표준 준수
