# 대시보드 - 매출 집계 - 구현 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 대시보드 / 매출 집계
**SDLC 단계:** 구현
**변경 요점 (vs 1차):** DELIVERED 필터, 기간 파라미터, 월 매출 분리 응답.

## 1. 구현 범위

OrderRepository에 상태+기간 SUM 쿼리 추가, SalesResponse DTO 확장, Controller에 기간 파라미터 노출.

## 2. 구현 항목 체크리스트

- [ ] `@Query("SELECT COALESCE(SUM(o.totalAmount),0) FROM Order o WHERE o.status=:status AND o.orderDate BETWEEN :from AND :to")` 작성
- [ ] SalesResponse DTO 확장 (`currentMonthSales`, `previousMonthSales`)
- [ ] Service.getSales(LocalDate from, LocalDate to)
- [ ] from/to 검증 (from ≤ to, 미지정 시 epoch~now)
- [ ] 단위/통합 테스트

## 3. 적용 기술

- JPA `@Query` + `COALESCE`
- `YearMonth` 기반 월 경계 계산
- DTO에 from/to echo

## 4. 단계별 작업 순서

1. SUM 쿼리 → 2. 월 경계 계산 유틸 → 3. DTO → 4. Service → 5. Controller → 6. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 인덱스 부재 시 SUM이 풀스캔 | `(status, order_date)` 인덱스 권장 |
| 시간대(timezone) 처리 혼란 | 서버 timezone을 KST로 고정, DB에도 KST 저장 |

## 6. 검증 포인트

- 기간 외 주문이 합계에 포함되지 않는지
- DELIVERED 외 상태가 0원으로 처리되는지
- 월말 자정 경계 정확성
