# 주문 관리 - 주문 상태 관리 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 주문 관리 / 주문 상태 관리
**SDLC 단계:** 설계

## 1. 설계 개요

상태는 Order 엔티티의 `status` 컬럼으로 관리한다. 별도 상태 변경 API를 두며, 전이 규칙은 1차에서 명문화하지 않는다(임의 전이 허용).

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | OrderController | 상태 변경 API |
| Service | OrderService | status 검증·저장 |
| Entity | Order | status 컬럼 |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 |
|---|---|---|
| status | varchar(20) | NOT NULL, enum 5종 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| PATCH | /api/orders/{id}/status | 상태 변경 (body: { status }) |

## 5. 처리 흐름

1. 입력 status가 enum 값인지 검증
2. Order 조회 → status 변경 → save
3. status가 CANCELLED면 [[재고연동]]으로 재고 복원

## 6. 설계 규칙

- enum 외 값 거부.
- 전이 규칙(예: SHIPPED → PENDING 금지) 없음.
- 동일 status로 재변경 허용.
