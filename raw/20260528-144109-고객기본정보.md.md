# 고객 관리 - 고객 기본정보 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 고객 관리 / 고객 기본정보
**SDLC 단계:** 설계

## 1. 설계 개요

고객 CRUD를 Controller → Service → Repository 3계층으로 구현. **email은 unique 제약을 두지 않는다**.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | CustomerController | CRUD API |
| Service | CustomerService | 필수값·이메일 형식 검증 |
| Entity | Customer | 고객 모델 |
| Repository | CustomerRepository | JPA Repository |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint | PK |
| name | varchar(80) | NOT NULL |
| email | varchar(120) | NOT NULL |
| phone | varchar(30) | NOT NULL |
| address / city / country | varchar | nullable |
| created_at | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/customers | 등록 |
| GET | /api/customers | 목록 |
| GET | /api/customers/{id} | 상세 |
| PUT | /api/customers/{id} | 수정 |
| DELETE | /api/customers/{id} | 삭제 |

## 5. 처리 흐름

- 등록: 필수·형식 검증 → save → 201
- 삭제: 존재 검증 → delete → 204 (주문 참조 검사 없음)

## 6. 설계 규칙

- email UNIQUE 제약 없음.
- 응답은 [[공통API응답]] 표준.
