# 공통/인프라 - 전역 예외 처리 - 요구사항 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 공통/인프라 / 전역 예외 처리
**SDLC 단계:** 요구사항

## 1. 개요

각 도메인에서 발생하는 예외를 중앙 한 곳에서 잡아 일관된 응답 형태로 변환한다. 1차에서는 단순 분류만 한다.

## 2. 사용자 시나리오

- 프론트엔드 개발자가 4xx/5xx 응답을 형태 일관되게 받는다.
- 운영자가 예외 발생 시 서버 로그에서 stacktrace를 확인한다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 예외-01 | 단일 핸들러 | `@ControllerAdvice`로 모든 예외 포착 | 필수 |
| 예외-02 | 500 일괄 | 처리되지 않은 예외 → 500 | 필수 |
| 예외-03 | 400 검증 실패 | Validation 오류는 400 | 필수 |
| 예외-04 | 로그 적재 | 모든 예외를 ERROR 레벨로 로그 | 필수 |

## 4. 응답 정보

- HTTP 상태코드 + 공통 API 응답(`success=false`).

## 5. 업무 규칙

- 1차에서는 errorCode·message 별도 제공 안 함.
- stacktrace는 응답에 포함하지 않음(로그에만).

## 6. 비기능 요구사항

- 예외 변환으로 인한 추가 지연 10ms 이내.

해당 핸들러 자체.
