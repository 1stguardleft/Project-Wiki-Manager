# 상품 관리 - 상품 기본정보 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 상품 관리 / 상품 기본정보
**SDLC 단계:** 설계

## 1. 설계 개요

상품 마스터 CRUD를 Controller → Service → Repository 3계층으로 구현한다. SKU/카테고리 unique 제약은 두지 않는다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | ProductController | 상품 CRUD API |
| Service | ProductService | 비즈니스 로직 |
| Entity | Product | 상품 모델 |
| Repository | ProductRepository | JPA Repository |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| id | bigint | PK, auto-inc | |
| name | varchar(120) | NOT NULL | 상품명 |
| price | bigint | NOT NULL | 판매가 |
| sku | varchar(60) | NOT NULL | 식별자 |
| category | varchar(40) | NOT NULL | 카테고리 |
| quantity | int | default 0 | 현재 재고 |
| description | varchar(500) | nullable | 설명 |
| created_at | timestamp | NOT NULL | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/products | 등록 |
| GET | /api/products | 목록 |
| GET | /api/products/{id} | 상세 |
| PUT | /api/products/{id} | 수정 |
| DELETE | /api/products/{id} | 삭제 |

## 5. 처리 흐름

- 등록: 필수 검증 → save → 201 응답
- 수정: 존재 검증 → 변경 → 200 응답
- 삭제: 존재 검증 → delete → 204 응답

## 6. 설계 규칙

- SKU/이름 unique 제약 없음.
- 가격 음수 검증은 Service 레이어에서 수행.
- 응답은 [[공통API응답]] 표준 준수.
