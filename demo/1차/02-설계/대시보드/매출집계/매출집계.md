# 대시보드 - 매출 집계 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 대시보드 / 매출 집계
**SDLC 단계:** 설계

## 1. 설계 개요

매출 합계는 전체 주문의 `totalAmount`를 합산해 단일 정수로 반환한다. 별도 매출 테이블은 두지 않는다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | DashboardController | 매출 API 노출 |
| Service | DashboardService | 매출 합계 계산 |
| Repository | OrderRepository | sumTotalAmount() |

## 3. 데이터 / 항목

자체 엔티티 없음.

| 항목 | 타입 | 설명 |
|---|---|---|
| totalSales | long | 전체 주문 totalAmount의 합계 |

## 4. 인터페이스 (API)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/dashboard/sales | 전체 매출 합계 |

## 5. 처리 흐름

1. 클라이언트가 매출 API 호출
2. Service가 OrderRepository의 합계 쿼리 호출
3. 결과를 DTO로 반환

## 6. 설계 규칙

- 주문 상태와 무관하게 모두 합산.
- 합계 쿼리는 SQL 레벨에서 `SUM`을 사용한다.
