# 대시보드 - 운영 알림 지표 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 대시보드 / 운영 알림 지표
**SDLC 단계:** 설계

## 1. 설계 개요

접수 대기 주문 수와 재고 부족 상품 수를 단일 호출로 묶어 반환하는 운영 알림 API. 별도 알림 테이블은 두지 않고 **그때그때 집계**해 가져온다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | DashboardController | 알림 지표 API 노출 |
| Service | DashboardService | 두 카운트를 묶어 계산 |
| Repository | OrderRepository | countByStatus(PENDING) |
| Repository | ProductRepository | countByQuantityLessThan(10) |

## 3. 데이터 / 항목

자체 엔티티 없음. 응답 DTO에 2개 정수 필드 포함.

| 항목 | 타입 | 설명 |
|---|---|---|
| pendingOrders | long | PENDING 주문 수 |
| lowStockItems | long | quantity < 10 상품 수 |

## 4. 인터페이스 (API)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/dashboard/alerts | 운영 알림 지표 일괄 조회 |

## 5. 처리 흐름

1. 클라이언트가 알림 API 호출
2. Service가 두 Repository 쿼리를 병렬/순차로 호출
3. 결과를 DTO로 묶어 반환

## 6. 설계 규칙

- 재고 임계값 10은 **상수로 코드에 박혀 있다**(파라미터 미노출).
- 알림 이력은 보존하지 않는다.
