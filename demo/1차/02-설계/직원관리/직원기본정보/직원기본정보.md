# 직원 관리 - 직원 기본정보 - 설계 (1차)

**문서 버전:** v1.0 (1차)
**도메인 / 서브도메인:** 직원 관리 / 직원 기본정보
**SDLC 단계:** 설계

## 1. 설계 개요

직원 CRUD를 3계층으로 구현. email은 UNIQUE 제약 없이 NOT NULL만.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | EmployeeController | CRUD |
| Service | EmployeeService | 검증·부서 존재 확인 |
| Entity | Employee | 모델 |
| Repository | EmployeeRepository | JPA |

## 3. 데이터 모델

| 컬럼 | 타입 | 제약 |
|---|---|---|
| id | bigint | PK |
| name | varchar(80) | NOT NULL |
| email | varchar(120) | NOT NULL |
| phone | varchar(30) | NOT NULL |
| position | varchar(40) | NOT NULL |
| salary | bigint | nullable |
| hire_date | date | nullable |
| department_id | FK | NOT NULL |
| created_at | timestamp | 자동 |

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | /api/employees | 등록 |
| GET | /api/employees | 목록 |
| GET | /api/employees/{id} | 상세 |
| PUT | /api/employees/{id} | 수정 |
| DELETE | /api/employees/{id} | 삭제 |

## 5. 처리 흐름

- 등록: 필수·이메일 형식·부서 존재 검증 → save → 201
- 삭제: 존재 검증 → delete → 204

## 6. 설계 규칙

- email UNIQUE 없음.
- department_id NOT NULL.
- 응답은 [[공통API응답]] 표준.
