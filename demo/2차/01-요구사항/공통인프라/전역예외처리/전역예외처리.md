# 공통/인프라 - 전역 예외 처리 - 요구사항 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 공통/인프라 / 전역 예외 처리
**SDLC 단계:** 요구사항
**변경 요점 (vs 1차):** 400/404/409/500 분리, errorCode 표준화, message 메시지 매핑.

## 1. 개요

예외 타입과 도메인 정책에 따라 적절한 HTTP 상태코드와 errorCode를 부여해 클라이언트가 분기 처리할 수 있게 한다.

## 2. 사용자 시나리오

- 프론트엔드가 `errorCode = DUPLICATE_SKU` 응답에서 "이미 등록된 SKU" 안내를 띄운다.
- 운영자가 errorCode로 로그를 필터링해 같은 유형의 사고를 찾는다.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 예외-01 | 검증 실패 → 400 | Validation/IllegalArgument | 필수 |
| 예외-02 | 미존재 → 404 | EntityNotFound 등 | 필수 |
| 예외-03 | 충돌 → 409 | DataIntegrityViolation, 도메인 정책 위반 | 필수 |
| 예외-04 | 알 수 없음 → 500 | 그 외 모든 예외 | 필수 |
| 예외-05 | errorCode 표준 | enum 또는 상수로 관리 (신규) | 필수 |

## 4. errorCode 카탈로그(일부)

| errorCode | HTTP | 의미 |
|---|---|---|
| VALIDATION_FAILED | 400 | 일반 검증 실패 |
| INVALID_EMAIL | 400 | 이메일 형식 위반 |
| INVALID_CATEGORY / INVALID_POSITION / INVALID_SKU_FORMAT | 400 | enum/형식 |
| INVALID_PERIOD | 400 | 기간 파라미터 |
| NOT_FOUND | 404 | 일반 미존재 |
| DUPLICATE_SKU / DUPLICATE_EMAIL / DUPLICATE_NAME | 409 | unique 위반 |
| INSUFFICIENT_STOCK | 409 | 재고 부족 |
| INVALID_TRANSITION | 409 | 상태 전이 위반 |
| PRODUCT_IN_USE / CUSTOMER_IN_USE / DEPARTMENT_IN_USE | 409 | 사용 중 삭제 |
| UNKNOWN_ERROR | 500 | 그 외 |

## 5. 업무 규칙

- errorCode는 ALL_CAPS_SNAKE_CASE.
- message는 사용자에게 보여줄 수 있는 한글 안내.
- stacktrace는 응답에 미노출.

## 6. 비기능 요구사항

- 예외 변환 추가 지연 10ms 이내.

## 7. 예외 처리

핸들러 자체. 처리 중 추가 예외는 UNKNOWN_ERROR로 폴백.
