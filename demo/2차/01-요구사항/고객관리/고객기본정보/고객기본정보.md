# 고객 관리 - 고객 기본정보 - 요구사항 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 고객 관리 / 고객 기본정보
**SDLC 단계:** 요구사항
**변경 요점 (vs 1차):** email UNIQUE 적용, 이메일 형식 검증 강화, 활성 주문 보유 고객 삭제 차단.

## 1. 개요

거래처/소비자 마스터의 품질을 높이기 위해 이메일을 고객 식별자로 격상하고, 중복 등록을 차단한다. 활성 주문이 있는 고객은 삭제할 수 없도록 한다.

## 2. 사용자 시나리오

- 영업 담당자가 이미 등록된 이메일로 신규 등록 시도 → 즉시 차단.
- 매니저가 활성 주문을 보유한 고객을 삭제 시도 → 차단 안내.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 고객-01 | 등록 | 신규 고객 등록 | 필수 |
| 고객-02 | 목록 | 전체 조회 | 필수 |
| 고객-03 | 상세 | 단건 조회 | 필수 |
| 고객-04 | 수정 | 정보 변경 | 필수 |
| 고객-05 | 삭제 | 활성 주문 없을 때만 | 필수 |
| 고객-06 | 이메일 중복 검증 | 동일 이메일 등록 차단 (신규) | 필수 |

## 4. 관리 정보

| 항목 | 필수 | 형식 | 설명 |
|---|---|---|---|
| name | 필수 | 1~80자 | 고객명 |
| email | 필수 | 이메일 형식, UNIQUE | 이메일 |
| phone | 필수 | E.164 권장 | 전화번호 |
| address / city / country | 선택 | 문자열 | 주소 |

## 5. 업무 규칙

- email은 시스템 전체에서 unique.
- 활성 주문(PENDING/CONFIRMED/SHIPPED) 보유 고객 삭제 불가.
- 이메일 형식은 RFC 5322 기준 검증.

## 6. 비기능 요구사항

- 등록·수정 응답 0.5초 이내.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 이메일 중복 | 409 DUPLICATE_EMAIL |
| 이메일 형식 위반 | 400 INVALID_EMAIL |
| 활성 주문 보유 삭제 | 409 CUSTOMER_IN_USE |
