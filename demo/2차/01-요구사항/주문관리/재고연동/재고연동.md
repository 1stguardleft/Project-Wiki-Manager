# 주문 관리 - 재고 연동 - 요구사항 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 주문 관리 / 재고 연동
**SDLC 단계:** 요구사항
**변경 요점 (vs 1차):** 재고 부족 시 등록 거부, 주문 삭제 시 재고 복원, 모든 변동을 StockHistory에 기록.

## 1. 개요

음수 재고를 원천적으로 막고, 모든 재고 변동을 이력으로 적재해 추적 가능하게 한다. 삭제로 인한 재고 손실도 자동 복원한다.

## 2. 사용자 시나리오

- 영업 담당자가 재고 0인 상품으로 주문 시도 → 즉시 거부.
- 운영자가 등록 직후 잘못 들어온 주문을 DELETE → 재고 자동 복원.

## 3. 기능 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| 연동-01 | 등록 시 차감 + 부족 거부 | quantity 부족 시 409 (변경) | 필수 |
| 연동-02 | CANCELLED 복원 | 1차와 동일 | 필수 |
| 연동-03 | 삭제 시 복원 | 주문 DELETE 시도 복원 (신규) | 필수 |
| 연동-04 | 이력 적재 | 모든 변동을 [[재고관리]] StockHistory에 기록 (신규) | 필수 |

## 4. 관리 정보

| 항목 | 설명 |
|---|---|
| product.quantity | 변동 |
| StockHistory(reason) | ORDER / CANCEL / ADJUST |

## 5. 업무 규칙

- 변동 후 quantity 음수 → 409 INSUFFICIENT_STOCK.
- 변동은 모두 트랜잭션 내 수행.
- DELETE도 status가 CANCELLED가 아닌 경우 복원.

## 6. 비기능 요구사항

- 추가 지연 100ms 이내.

## 7. 예외 처리

| 상황 | 처리 |
|---|---|
| 재고 부족 | 409 INSUFFICIENT_STOCK |
| 동시 차감 race | 트랜잭션 + 락으로 일관성 보장 |
