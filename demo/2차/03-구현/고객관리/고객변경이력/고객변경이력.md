# 고객 관리 - 고객 변경 이력 - 구현 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 고객 관리 / 고객 변경 이력
**SDLC 단계:** 구현
**변경 요점 (vs 1차):** CustomerHistory 엔티티/Repository, Service의 변경 감지 + 적재 로직.

## 1. 구현 범위

CustomerHistory 엔티티 + Repository를 신설하고, CustomerService.update에 변경 감지 + 이력 적재 로직을 추가한다.

## 2. 구현 항목 체크리스트

- [ ] CustomerHistory 엔티티 (7개 컬럼)
- [ ] CustomerHistoryRepository (findByCustomerIdOrderByChangedAtDesc)
- [ ] CustomerService.update: 변경 전 스냅샷 → save → 필드별 diff → 이력 insert
- [ ] `GET /api/customers/{id}/history` 핸들러
- [ ] 트랜잭션(@Transactional) 적용
- [ ] 단위/통합 테스트

## 3. 적용 기술

- JPA `@Transactional`
- 필드 비교 유틸 (null-safe equals)

## 4. 단계별 작업 순서

1. 엔티티/Repo → 2. update 메서드 리팩터링 → 3. 컨트롤러 → 4. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 동시 수정 시 이력 적재 순서 혼선 | @Transactional + DB 트랜잭션 격리 |
| 이력 테이블 폭증 | 인덱스(customer_id, changed_at), 보존 정책 |

## 6. 검증 포인트

- 변경 없는 필드는 row 미생성
- 동시 두 필드 변경 시 row 2건 적재
