# 대시보드 - 운영 알림 지표 - 구현 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 대시보드 / 운영 알림 지표
**SDLC 단계:** 구현
**변경 요점 (vs 1차):** threshold query 처리, staleOrders 쿼리 추가, 응답 DTO 확장.

## 1. 구현 범위

`/api/dashboard/alerts`에 threshold·staleOrders를 도입. PENDING 주문 중 24시간 이상 경과한 건을 별도로 카운트한다.

## 2. 구현 항목 체크리스트

- [ ] OrderRepository에 `countByStatusAndOrderDateBefore(status, time)` 추가
- [ ] AlertsResponse DTO 확장 (`staleOrders`, `threshold`)
- [ ] DashboardService.getAlerts(int threshold) 작성
- [ ] threshold 클램프 로직 (1~1000)
- [ ] Controller에 `@RequestParam(defaultValue="10")` 적용
- [ ] 단위/통합 테스트

## 3. 적용 기술

- Spring `@RequestParam` 기본값/검증
- JPA derived query (`countByStatusAndOrderDateBefore`)
- `LocalDateTime.now().minusHours(24)`

## 4. 단계별 작업 순서

1. Repository 메서드 추가 → 2. 클램프 유틸 → 3. Service → 4. Controller → 5. 테스트

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| `orderDate` 인덱스 부재로 staleOrders 쿼리 느려짐 | DDL에 `idx_order_status_date` 추가 권장 |
| threshold 외부화로 부하 증가 가능 | 동일 쿼리 패턴이라 영향 적음, 모니터링 |

## 6. 검증 포인트

- threshold=0/5/100/-1/abc 각 케이스
- staleOrders가 정확히 24시간 경과분만 잡는지
