# 주문 관리 - 재고 연동 - 설계 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 주문 관리 / 재고 연동
**SDLC 단계:** 설계
**변경 요점 (vs 1차):** 재고 부족 검증 + DELETE 복원 + StockHistory 적재.

## 1. 설계 개요

OrderService의 등록/취소/삭제 흐름에 [[재고관리]] StockHistory 적재를 통합하고, 음수 재고를 차단한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Service | OrderService | 흐름 오케스트레이션 |
| Service | ProductService | adjustStock(id, delta, reason, memo) |
| Entity | StockHistory | [[재고관리]] 참조 |

## 3. 처리 흐름

- 등록: `product.quantity - order.quantity ≥ 0` 검증 → adjustStock(-qty, ORDER) → 실패 시 409
- CANCELLED 전이: adjustStock(+qty, CANCEL)
- DELETE: status가 CANCELLED가 아니면 adjustStock(+qty, CANCEL)

## 4. 설계 규칙

- 재고 변경 + StockHistory 적재는 동일 트랜잭션.
- 비관적 락(`SELECT ... FOR UPDATE`) 또는 낙관적 락으로 race condition 보호.
- 음수 결과 시 트랜잭션 롤백.
