# 주문 관리 - 주문 조회 필터 - 설계 (2차)

**문서 버전:** v2.0 (2차)
**도메인 / 서브도메인:** 주문 관리 / 주문 조회 필터
**SDLC 단계:** 설계
**변경 요점 (vs 1차):** 통합 검색 API 신설, Specification/JPQL 기반 다중 조건, 페이지네이션, 인덱스 추가.

## 1. 설계 개요

다중 조건 필터를 Spring Data Specification 또는 JPQL로 처리하고, Pageable로 페이지네이션한다.

## 2. 구성 요소

| 계층 | 구성 요소 | 역할 |
|---|---|---|
| Controller | OrderController | 통합 검색 핸들러 |
| Service | OrderService | 조건 조립 |
| Repository | OrderRepository | Specification 적용 |

## 3. 데이터 모델

추가 컬럼 없음. 인덱스 추가:

- `idx_order_status_date (status, order_date)`
- `idx_order_customer_date (customer_id, order_date)`
- `idx_order_employee_date (employee_id, order_date)`

## 4. API 인터페이스

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | /api/orders/search?customerId=&status=&from=&to=&employeeId=&page=&size= | 통합 검색 |

## 5. 처리 흐름

1. 파라미터 추출 + 검증(from ≤ to, status enum)
2. Specification 조립
3. `orderRepository.findAll(spec, pageable)`
4. DTO 매핑

## 6. 설계 규칙

- 모든 파라미터 선택.
- size 기본 20, 최대 100.
- 1차 경로(`/customer/{id}`, `/status/{s}`)는 한 릴리스 유지(deprecated 헤더).
