# 상세설계수립 (쉬운 버전)

## 1. 에이전트 페르소나 — "누가 무엇을 하는가"

이 시스템은 단일 챗봇이 아니라 **LangGraph 파이프라인의 13개 노드(=에이전트)** 가 차례로 일을 처리한다. 각 노드는 자기 책임만 갖고, 다음 노드에 결과를 넘긴다.

| # | 이름 | LLM? | 한 줄 역할 |
|---|------|------|-----------|
| 1 | **fetch** (수집) | ✕ | 입력(URL/파일/붙여넣기)을 마크다운으로 받아 `raw/`에 원본 보존 |
| 2 | **parse** (파싱) | ✕ | 과다 개행 등 노이즈 정리 |
| 3 | **normalize** (정규화) | ✔ | 위키용 깔끔한 마크다운으로 재구성 + SDLC 단계 분류 + slug 생성 |
| 4 | **decompose** (도메인 분해) | ✔ | 도메인 > 서브도메인 2계층으로 분류. 복합 문서는 자식 run으로 쪼갬 |
| 5 | **chunk** (청킹) | ✕ | 헤딩 단위 분할, 긴 섹션은 1,600자(겹침 200자) 캡 |
| 6 | **embed** (임베딩) | 모델 | 청크를 벡터화(1536차원)해 Chroma에 저장 |
| 7 | **similarity** (유사도) | ✔ | 벡터로 후보를 뽑고 LLM이 "병합/신규" 판정 |
| 8 | **conflict** (충돌판정) | ✔ | 병합 대상이 있을 때 모순/보강/중복 분류 |
| 9 | **merge** (병합) | ✔ | 신규 생성 또는 기존 페이지에 병합. 충돌 시 정책으로 분기 |
| 10 | **verify** (누락검토) | ✔ | 병합 결과에서 정보 누락 여부 점검, 누락 시 1회 재머지 |
| 11 | **crossref** (상호참조) | ✔ | 관련 페이지를 `implements/verifies/refines/relates_to` 엣지로 연결 |
| 12 | **index** (인덱싱) | ✕ | `index.md` 카탈로그·검색 인덱스 재생성 |
| 13 | **log** (로깅) | ✕ | 처리 결과를 `log.md`에 한 줄 이력으로 추가 |

각 LLM 노드는 한국어 기술문서체로 응답하며, 사실 창작은 금지된다. `OPENAI_API_KEY`가 없으면 **결정적 폴백**(요약=정제, 해시 임베딩, 거리 게이트만 사용)으로 동작해 오프라인에서도 전체 파이프라인이 굴러간다.

## 2. 워크플로우 — "어떻게 흐르는가"

### 2.1 처리 순서

```
START → fetch → parse → normalize → decompose
      → (단일 도메인) chunk → embed → similarity → conflict
      → merge → verify → (누락 시 merge 재시도)
      → crossref → index → log → END
```

- **단계 1 (입력 분석)**: `fetch → parse → normalize`로 원본을 위키 형태로 변환하고 SDLC 단계를 분류.
- **단계 2 (분기 판단)**:
  - `decompose`: 복수 도메인이면 자식 run을 띄우고 부모는 종료.
  - `similarity`: 거리·단계·서브도메인 가드를 통과한 후보만 LLM에 판정 요청 → `merge` 또는 `create`.
  - `conflict`: 병합 대상이 있을 때만 실행.
- **단계 3 (실행)**: `merge`로 통합, `verify`가 누락을 검사(최대 1회 재시도), `crossref`로 의미 관계 엣지 추가, `index`·`log`로 마무리.

### 2.2 상태 관리

- **턴 = run**: 적재 1건마다 `run_id`가 발급되고, LangGraph가 `IngestState`(TypedDict)를 노드 간 공유.
- 주요 상태 필드: `source`, `normalized_md`, `sdlc_phase / slug / domain / subdomain`, `chunks / vector_ids`, `similar_candidates / merge_decision / conflict_report`, `coverage_report`, `edges`, `errors`.
- 각 노드는 실행 전후로 `queued → running → succeeded/failed` 이벤트를 **per-run 이벤트 버스(SSE)** 에 발행 → React Flow가 실시간 시각화.
- 가시성을 위해 `STEP_DELAY_SEC`(기본 1초) 지연을 둔다.

## 3. 도구(서비스 함수) — "각 노드가 부르는 함수"

OpenAI Function Calling이 아니라, 노드가 직접 호출하는 **서비스 함수**들이다.

| 함수 | 설명 |
|------|------|
| `parser.parse_source` / `save_raw` | 입력을 마크다운으로 파싱, 원본을 `raw/`에 타임스탬프로 저장 |
| `llm.chat` | 모든 LLM 노드의 공용 추론 인터페이스 (JSON 모드·temperature 옵션) |
| `llm.embed` | 텍스트 임베딩 (오프라인 시 해시 기반 폴백) |
| `chunking.chunk_markdown` | 헤딩 분할 + 길이 캡 청킹 |
| `vectordb.upsert_chunks` / `query` | Chroma에 청크 저장 / 코사인 거리 기반 유사 청크 검색 |
| `wiki_engine.read_page` / `write_page` | 위키 페이지 파일 CRUD |
| `wiki_engine.add_edge` | `edges.jsonl`에 그래프 엣지 추가 |
| `wiki_engine.rebuild_index` / `append_log` | 카탈로그·이력 갱신 |
| `merge_store.create` / `update` | 병합 레코드(before/after/conflicts/coverage) 저장 |
| `resolvers.resolve` | 충돌 정책(llm_merge / manual / prefer_incoming / prefer_existing) 분기 |
| `runs.new_run` | 신규 run 생성·큐잉 |

## 4. RAG·메모리 전략

### 4.1 참조 데이터

1. 위키 페이지 (`wiki/`, frontmatter + 본문)
2. 원본 raw 소스 (`raw/`, 불변)
3. 지식 그래프 (`wiki/graph/edges.jsonl`)
4. 확정 스키마/택소노미 (`schema/*.yaml`)

검색은 **하이브리드(BM25 + 벡터 RRF 융합)**, 질의응답은 페이지 근거를 인용해 LLM이 합성한다.

### 4.2 청킹·임베딩·벡터DB

- **청킹**: 마크다운 헤딩 분할 후 약 1,600자 캡, 오버랩 200자. 메타데이터로 `page_slug / sdlc_phase / heading` 부착.
- **임베딩 모델**: `text-embedding-3-small` (1536차원). 키가 없으면 해시 기반 폴백.
- **Vector DB**: Chroma `PersistentClient`(`.chroma/`), 단일 컬렉션 `wiki`, 코사인 거리.

### 4.3 메모리 2계층

- **단기 (휘발성)**: run별 `IngestState`. run이 끝나면 사라진다. 누락검토 보완 루프 상태도 여기 포함.
- **장기 (영속)**: 위키 파일 + Chroma 벡터 + `edges.jsonl` + `log.md` + 병합 레코드 + 적재 매니페스트(`ingested.json`).
- 초기화는 `POST /api/wiki/reset` — 생성물은 비우고 raw 원본은 보존한다.

## 5. 핵심 기술 선택

| 구분 | 선택 | 이유 |
|------|------|------|
| **LLM 모델** | `gpt-4o-mini` (기본), Azure OpenAI 지원, 오프라인 폴백 | 적재당 LLM 호출이 8회 — 비용·속도가 중요. JSON 모드·한국어 양호. 키 없이도 데모 가능 |
| **에이전트 프레임워크** | LangGraph `StateGraph` + per-run SSE 이벤트 버스 | 조건부 엣지로 분기·루프(분해 split, 누락검토 loop)를 제어. 노드 단위 이벤트로 실시간 시각화에 적합 |
| **프롬프트 전략** | 역할 분리 시스템 프롬프트 + LLM-as-Judge + 인라인 Few-shot | 단일 책임 강제로 재현성↑. "후보는 벡터, 판정은 LLM" 패턴으로 정밀도 확보 |
| **출력 파싱** | OpenAI JSON Mode + 실패 시 보수적 폴백 | 분해/유사도/충돌/누락/상호참조는 구조화 출력 필요. 파싱 실패 시에도 파이프라인이 멈추지 않게 안전 기본값으로 진행 |
| **모니터링** | per-run SSE (`node_update`: 상태·소요시간·요약/상세) + Console | 멀티 에이전트 실행을 React Flow에서 실시간으로 보여주는 것이 핵심 가치. 외부 추적 도구 없이 자체 이벤트 스트림으로 충분 |
