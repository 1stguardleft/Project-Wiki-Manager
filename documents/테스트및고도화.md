## 주요 문제 해결 및 기술 리서치 (테스트 단계)

테스트 중 발견된 엣지 케이스와 병목을 해결하기 위해 리서치하고 적용한 내용을 정리한다.

| **이슈 구분** | **문제 상황 및 원인** | **리서치 및 해결 과정** |
| --- | --- | --- |
| **품질 / 환각** | 두 문서를 LLM이 한 페이지로 합칠 때 **한쪽의 일부 조항을 누락**하는 경우 발생. 한 번 패스로는 검증이 안 됨. | • **리서치:** LangGraph의 조건 분기 + bounded retry 패턴.<br>• **적용:** 병합 뒤 **누락 검토(verify) 단계**를 두고, 빠진 조항이 있으면 **병합으로 1회만 되돌려** 보완하도록 그래프 분기 추가. 무한 루프는 횟수 상한으로 차단. |
| **속도 / 지연** | 한 문서에 여러 도메인이 섞여 있으면 13단계를 다 거치는 동안 한 건 적재가 길어짐. | • **리서치:** Multi-Agent 워크플로우의 fan-out 패턴 + LangGraph 자식 run.<br>• **적용:** **도메인 분해(decompose) 단계**가 다도메인을 감지하면 도메인 단위로 **자식 run을 생성해 병렬 처리**. 프론트엔드는 **한 화면에서 여러 분기 진행을 동시에 시각화**(branch-panel). |
| **보안 / 가드레일** | 위키 데이터 초기화처럼 **되돌릴 수 없는 destructive 작업**을 실수로 누를 위험. SSE 연결이 끊길 때 화면이 빈 상태로 남을 위험. | • **리서치:** 파괴적 액션의 두 단계 확인 패턴 / SSE 재연결 시 history replay.<br>• **적용:** 초기화 버튼은 **확인 행(confirm row)을 한 번 더** 띄우고 키보드 포커스를 위험 버튼으로 강제 이동. 백엔드는 **원본(raw)은 건드리지 않고** 위키 데이터만 삭제. SSE 끊김 시 브라우저 자동 재연결 + 백엔드가 이력 재전송으로 캔버스 보존. |

## 1. LLM 답변 품질 평가 및 개선

| 항목 | 내용 |
| --- | --- |
| 평가 대상 기능 | 중복 페이지 자동 감지 + LLM 자동 병합 + 인용 기반 질의응답 |
| 평가 방식 | 데모 문서 4건(로그인 v1/v2, 결제 설계, 결제 테스트)으로 end-to-end 적재 후 **누락 검토 단계가 자동 산출하는 커버리지 점수**와 **수동 검토** 병행 |
| 평가 결과 (초기) | 벡터 유사도만 사용 시 단어만 비슷한 다른 문서를 같다고 판정하는 false-positive 발생. 자동 병합 본문에서 v1/v2 일부 조항 누락. |
| 개선 조치 | • 유사도/충돌/상호참조 판정에 **벡터(후보) + LLM(최종) 2단계** 분리 도입<br>• LLM 호출 시 **JSON 모드 강제** + 판단 근거 동시 출력<br>• 병합 뒤 **누락 검토 → 1회 재병합** 루프 추가 |
| 개선 후 결과 | 데모 시나리오 기준 false-positive 0건, 병합 누락 0건(누락 검토 커버리지 100%), 답변에 항상 인용 슬러그가 같이 표기됨. |

## 2. 성능 및 비용 최적화

| 항목 | 내용 |
| --- | --- |
| 기존 병목 | 다중 도메인 문서가 13단계를 순차 처리하면 적재 시간이 길어짐. LLM 호출 빈도/비용 부담. |
| 개선 전략 | (1) **도메인 단위 병렬 실행**, (2) **오프라인 폴백**으로 키 없는 데모 시 비용 0원 운영. |
| 적용 기술 | • LangGraph 조건 분기로 자식 run 분리, 부모는 페이지 생성 없이 종료<br>• 결정적 해시 임베딩(1536차원)으로 LLM/임베딩 API 없이도 동일 shape 유지 |
| 개선 결과 | • N개 도메인 문서가 ~N배 빠르게 처리(병렬 분기 수에 비례)<br>• 데모 환경에서 외부 API 호출 0건으로 비용 절감하면서 시각화·병합·검색·인용 답변까지 그대로 동작 |

## 3. 예외 처리 및 가드레일

| 항목 | 내용 |
| --- | --- |
| 차단 대상 | • 초기화 같은 destructive 액션의 실수<br>• 파이프라인 단계 실패(LLM/벡터 DB 오류 등)<br>• SSE 연결 단절로 인한 시각화 손실 |
| 탐지 방식 | • 프론트엔드: confirm row 2단계 UI<br>• 백엔드: 각 노드 try/except로 실패를 별도 상태로 발행<br>• SSE: `readyState`로 재연결 가능 여부 판단 |
| 대응 로직 | • 초기화 시 **원본 raw 문서는 보존**, 위키 데이터만 삭제<br>• 노드 실패는 `failed`로 발행해 화면에 빨간 표식, 후속 단계는 영향 없게 처리<br>• SSE 끊기면 브라우저가 자동 재연결, 백엔드가 **이벤트 이력을 처음부터 재전송**해 캔버스 그대로 복원 |
| 테스트 결과 | • 실수로 초기화 클릭한 사용자가 confirm 단계에서 취소 → 데이터 보존 확인<br>• 적재 중 강제로 SSE를 끊고 다시 연결 → 워크플로우 화면이 끊김 없이 복원됨<br>• 단일 노드에서 강제 예외 발생 → 화면에 `failed` 상태 표시, 다른 분기 정상 진행 |

## 4. 기타 문제 해결 사례

| 항목 | 내용 |
| --- | --- |
| **React Flow 캔버스 노드 사라짐** | SSE로 노드 상태가 빠르게 갱신될 때 ReactFlow 캔버스에서 노드/엣지가 갑자기 사라지고 fit-view로도 복구 안 되는 현상 발생. → **`useNodesState`/`useEdgesState` controlled 패턴 + `ReactFlowProvider`** 로 전환하고, **`ResizeObserver`** 로 컨테이너 변동 시 자동 재맞춤. |
| **워크플로우 우측 상세 패널 가독성** | 실행 중 단계를 따라가니 결과가 없어 "처리 중…"만 깜빡임. → 자동 추적을 **"가장 최근에 완료된 단계"** 결과를 표시하도록 변경. 자동 추적 토글 + 노드 클릭 시 고정, 빈 곳 클릭/Esc로 재개. |
| **위키 페이지 진입 시 위치 안내 부재** | 워크플로우의 "생성된 페이지 보기 →"로 진입했을 때 좌측 폴더 트리가 닫혀 있어 페이지가 어디에 속하는지 안 보임. → URL의 `?slug=`을 인식해 **폴더 경로를 자동으로 펼치고 해당 행으로 스크롤**. 트리를 자체 스크롤 컨테이너(sticky)로 만들어 우측 본문이 밀리지 않게 처리. |
