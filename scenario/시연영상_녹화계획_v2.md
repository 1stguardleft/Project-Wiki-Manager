# 시연 영상 녹화 계획 (v2 — 자동 워크스루 실행본)

> **v1 → v2 변경 요지**
> - **`documents/시나리오수립.md` 의 SC-001 ~ SC-006 시나리오 순서**대로 시연을
>   재구성. 각 시나리오 시작 전 **시나리오 타이틀 카드**(SC-ID + 상황·목표
>   요약)를 5초간 노출 → 시청자가 "지금 보는 화면이 어떤 시나리오인지"를
>   화면만으로 알 수 있게 한다.
> - **실행 스크립트**: `scenario/record-walkthrough.mjs` (Playwright)가 헤드리스
>   브라우저 + `recordVideo` 로 6개 시나리오를 순회.
> - **라이브 적재 1건** 포함: 같은 슬러그가 이미 있어 자연스럽게 **병합·충돌
>   경로**까지 한 흐름에서 시연(SC-001 → SC-002 연결).
> - **데모 엣지 1건 자동 주입 → 회수**: 지식 그래프(SC-006)에서 구조화
>   evidence 패널을 확실히 보이게 사전 주입하고, 녹화 끝나면 제거.
> - **해상도 1440×900** (16:10): 1280×800에서는 `.wiki-layout.has-rail` 본문 폭이
>   ~430px로 좁아져 "연관 도메인" 5컬럼 표가 글자 단위로 짜부라지는 회귀
>   (2026-05-28) 때문에 폭을 ~590px 확보하도록 상향.
> - **시간**: 약 **4분 30초 ± 20초** (SC-006 의 데모 엣지 직접 클릭 + 시나리오 카드 기본 hold 단축으로 약 2분 이상 축소).

## 0. v2가 *실제로* 만드는 산출물

| 산출물 | 경로 | 비고 |
|---|---|---|
| 자동 워크스루 영상 | `demo-recordings/walkthrough-YYYYMMDDHHMM.webm` | Playwright `recordVideo`, 1440×900 |
| 자막 사이드카 | `demo-recordings/walkthrough-YYYYMMDDHHMM.srt` | burn-in 자막과 동일한 SRT (후반 편집용) |
| mp4 변환본 | `demo-recordings/walkthrough-YYYYMMDDHHMM.mp4` | libx264 CRF22 (WALK_SKIP_MP4=1로 끌 수 있음) |
| 녹화 스크립트 | `scenario/record-walkthrough.mjs` | 재실행 가능 |
| 캡처 모음 | `scenario/shots/sc-{NNN}-*.png` | 슬라이드/문서 재사용용 |
| 본 계획 | `scenario/시연영상_녹화계획_v2.md` | 이 파일 |

자동 워크스루 산출물의 **한계**(투명 공개):
- 내레이션·BGM ❌ (별도 후반작업 필요)
- 마우스 커서 ❌ (Playwright 헤드리스 한계 — 클릭/호버 결과로 메시지 전달)
- 컷·디졸브 전환 ❌ (연속 단일 컷, 시나리오 카드로만 구분)

→ 외부 발표용 마스터 영상은 본 워크스루 영상에 v1 시나리오대로 후반작업을
얹는 것을 권장. 본 v2 결과물은 **시연 흐름 검증 + 슬라이드 캡처 소스**로
가치 충분.

## 2. 자동 워크스루 시나리오 (시나리오 순서 = SC-001 → SC-006)

> 각 시나리오 데모 시작 전 **시나리오 카드**(SC-ID / 시나리오명 / 상황·목표
> 요약 3줄)가 5.2초 노출 → 시청자가 "지금 무엇을 시연하는지" 자체적으로 알
> 수 있다. 데모 도중에는 화면 하단의 burn-in 자막(같은 SRT에 기록)으로 핵심
> 포인트를 보조 설명.
>
> **데모 내용은 시나리오수립.md 와 1:1 일치하지 않을 수 있음**(자동화 가능한
> 범위로 단순화 — 사용자 요구: "내용은 다르더라도 순서상으로만"). 시나리오의
> 핵심 아이디어를 한 컷씩 직관적으로 보여주는 것이 목표.

### Intro (~0:05)
- `/ingest` 진입, 전체 타이틀 카드 5초 노출
- **카드**: "Project Wiki Manager · LLM 멀티 에이전트가 자동으로 유지하는 위키 — 핵심 시나리오 6선"

### SC-001 — 단일 문서 적재 → 위키 페이지 자동 생성 (~0:05 ~ 1:00)
- **시나리오 카드** (5.2s)
- `/ingest` 파일 브라우저로 `2차/01-요구사항/고객관리/고객검색/고객검색.md` 진입
- 체크박스 선택
- **충돌 정책 셀렉트 노출**: 네 옵션을 1.3s 씩 순차로 노출(`llm_merge` → `manual` → `prefer_incoming` → `prefer_existing` → `llm_merge`) — 네이티브 dropdown 은 OS 가 그려 영상에 안 잡히므로 표시 텍스트를 직접 갈아 가며 보여 줌
- "분석 시작" → `/runs/{id}` 자동 이동
- 워크플로우가 몇 단계 진행되는 모습만 짧게 노출 — *에이전트 상세 설명은 SC-004 로 분리* (SC-001 자막은 "워크플로우를 통해서 문서를 적재합니다. 각 에이전트의 역할은 시나리오 4에서 자세히 살펴봅니다." 한 줄)
- **캡처**: `sc-001-ingest.png`, `sc-001-pipeline.png`

### SC-002 — 중복·충돌 문서 적재 → LLM 자동 병합 (~0:55 ~ 1:35)
- **시나리오 카드** (5.2s) — 같은 슬러그(1차)가 이미 있어 자연스럽게 병합 분기 진입
- (같은 run 페이지에서) 충돌판정 노드 클릭 → relation/summary 노출
- 병합 노드 클릭 → merge 본문/모드 노출
- `run_completed` 까지 대기, `pipeline-done` 상태 캡처
- **자막**: "같은 슬러그 — 충돌판정·병합 노드가 자동 진입" / "의미 관계 판정 후 본문 자동 병합"
- **캡처**: `sc-002-conflict.png`, `sc-002-merge.png`, `sc-002-pipeline-done.png`

### SC-003 — 위키 검색 및 질의응답 (~1:35 ~ 2:30)
- **시나리오 카드** (5.2s)
- `/wiki` 진입 → 하이브리드 검색 입력 `"고객 검색"` Enter → 결과 노출
- 질의 입력 `"고객 검색에서 지원하는 필터 조건은?"` Enter → 인용 기반 답변(약 6초 대기)
- **자막**: "하이브리드 검색 — 키워드 + 의미 벡터 결합" / "자연어 질의 — 근거 페이지를 인용한 답변"
- **캡처**: `sc-003-search.png`, `sc-003-query.png`

### SC-004 — 멀티 에이전트 워크플로우 실시간 시각화 (~2:30 ~ 4:00, 약 90s)
- **시나리오 카드** (5.2s)
- 방금 실행한 run 으로 복귀 (`/runs/{previous_id}`)
- 전체 13개 노드 캔버스 노출 + 자막: "13개 중 LLM 배지가 붙은 8개 에이전트를 파이프라인 순서대로 펼쳐 보겠습니다"
- **LLM 에이전트 8종을 순차 강조** — 각 노드를 `focusAgent()`(=클릭+sustain 펄스) 로 강조하고, *그 강조가 떠 있는 동안* 자막이 해당 에이전트 역할을 한 줄로 설명:
  1. 정규화 — 본문 정리 + SDLC 단계·도메인·서브도메인 분류
  2. 도메인 분해 — 여러 도메인 혼재 시 자식 run 으로 병렬 분기
  3. 임베딩 — 청크 벡터화 후 Chroma 저장
  4. 유사도 — 벡터 후보 추리고 LLM이 동일 페이지 여부 재판정
  5. 충돌판정 — 보강·중복·모순·구체화 4종 분류
  6. 병합 — 정책에 따라 두 본문을 한 페이지로 통합
  7. 누락검토 — 커버리지 검증, 부족 시 병합으로 자동 회귀
  8. 상호참조 — "연관 도메인" 표 + 그래프 엣지 동시 갱신
- **자막 톤**: 각 에이전트마다 *"OO — LLM이 무엇을 한다"* 한 줄 구조로 통일
- **캡처**: `sc-004-pipeline.png` + `sc-004-{normalize,decompose,embed,similarity,conflict,merge,verify,crossref}.png` (총 9장)
- **설계 의도**: SC-001/SC-002 에서 결과적인 관점("자동 분류된다", "자동 병합한다")으로 본 동일 노드를, SC-004 에서는 *각 LLM 에이전트가 하는 일*로 다시 쪼개 설명 — 같은 시스템을 두 관점으로 보여 줘 LLM 활용 부분을 부각.

### SC-005 — 병합 결과 검토 및 되돌림 (diff / revert) (~4:00 ~ 4:40)
- **시나리오 카드** (5.2s)
- `/merges` 이동 → 좌측 목록에서 방금 병합된 항목 클릭
- side-by-side diff 노출 (충돌 0건은 badge 자동 숨김 정책 그대로 시연)
- **자막**: "병합 전·후 라인 단위 diff와 되돌리기" / "충돌 0건은 노이즈를 줄이려 표시하지 않음"
- **캡처**: `sc-005-diff.png`

### SC-006 — 지식 그래프 탐색 (~4:40 ~ 5:50)
- **시나리오 카드** (5.2s)
- `/graph` 이동 (도메인 펼쳐진 기본 상태에서 시작 — `GraphExplorer.jsx` `collapsed` 초기값이 빈 Set)
- 9종 엣지 타입·신뢰도를 색으로 구분한 그래프 전체 노출
- **관계 1건만 골라 깊이 설명**: `[DEMO]` 엣지(`edges.jsonl` 마지막 — `injectDemo()` append 순서 보장)를 *직접* 클릭. 이전 회 회귀로 모든 엣지를 순회하며 패널 텍스트 매칭하느라 ~2분(3:40 ~ 5:40 구간) 낭비됐던 부분 제거. 클릭 후 보라색 글로우 강조 + 우측 evidence 팝업을 **scale(1.35) 로 확대** + 강조 그림자
- 다섯 단 구조를 자막으로 *차례차례* 설명:
  1. 요약 — 두 페이지가 어떤 점에서 연결되는지
  2. 연관 사유 — 왜 함께 봐야 하는지
  3. 근거 인용 — 양쪽 본문의 직접 인용
  4. 공유 개념 — 공통 개념·코드·식별자
  5. 함께 볼 때 — 같이 검토해야 할 시점
- ESC로 팝업 닫기 (자동으로 transform 원상복귀)
- **설계 의도**: 필터 데모(단계/도메인/cross-only) 는 정보가 분산돼 보여서 의도적으로 생략. *한 관계의 의미*를 확대·집중으로 보여 주는 쪽이 evidence 시스템의 가치를 더 잘 부각.
- **캡처**: `sc-006-graph-base.png`, `sc-006-edge-evidence.png` (확대 상태)

### 엔딩 (~5:50 ~ 6:20)

## 3. 실행 절차

```bash
# 1) 백엔드/프론트가 떠 있는지 확인
curl -s http://127.0.0.1:8000/api/health | head -c 80
curl -s http://localhost:5173 -o /dev/null -w "%{http_code}\n"

# 2) 녹화 시작 — 약 6분 후 완료 (mp4 변환 포함)
node scenario/record-walkthrough.mjs

# (옵션) mp4 변환 건너뛰기
WALK_SKIP_MP4=1 node scenario/record-walkthrough.mjs

# 3) 결과 확인
ls -lh demo-recordings/walkthrough-*.{webm,mp4,srt}
ls -lh scenario/shots/sc-*.png
```

`record-walkthrough.mjs` 가 하는 일:
- 시작 전 데모 엣지 1건 자동 주입
- 시나리오마다 타이틀 카드 + 캡션 + 캡처를 자동 진행
- 종료 시 데모 엣지 자동 회수
- recordVideo 결과 `.webm` → `demo-recordings/` 자동 이동 + mp4 변환(libx264)
- 콘솔/페이지 에러를 별도 로그(`/tmp/walkthrough.log`)에 남김
- 실패 지점이 모호하지 않게 **fail-loud**: 폴더/파일/노드/URL/입력 못 찾으면 throw
